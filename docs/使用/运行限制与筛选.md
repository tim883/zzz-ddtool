# 运行限制与筛选

本文集中说明处理数量与计数口径、组合预览的筛选语义、游戏侧筛选流程以及格子状态标记的当前支持范围。卡片的生成、勾选与必带操作见 [任务管理器使用说明](./任务管理器使用说明.md) 第 6 节。

## 1. 本次最多处理多少盘

配置：`task_chain` 中每个任务的 `max_discs`（新任务默认 100，至少 1；界面上的输入范围是 1—5000）。窗口「当前任务限制」里显示为「本次最多处理 N 个盘子」，切换任务会恢复各自的数量。

每个任务独立计数，前一个任务用满额度后继续下一个任务，不会占用后续任务的额度。扫描阶段已经跳过的格位不计数，打开详情处理的盘计 1。

计数口径：**点开并读出盘面的盘计 1 件处理**；之后不管是升级、打标还是什么都不做，都算。

「原本就有弃置标记、重新判断后维持不动」的盘也计 1 件，并进结果清单、计入「判定弃置」，但**不计入「实际打上弃置标记」**（没按 R 就不算那本账）。三本账各自独立：处理计数 / 判定弃置 / 实际打标。

结果总结里三列的关系是 **筛选后 − 扫描跳过 − 处理 = 未处理**。其中「筛选后」是游戏标题栏的筛选后总盘数（含满级、锁定、弃置），不是本轮扫到多深；「未处理」是还没被点开的盘，额度用满提前收工时就留在这里（含列表尾部没滚到的部分）。

旧配置中未填写任务级 `max_discs` 时，每个任务沿用 `run.max_discs` 作为默认额度；没有任务链的命令行运行仍使用 `run.max_discs`。

到上限后**停在原地，不翻页**——翻页尾巴上那下 Esc 按在网格会把仓库退到功能页。

### 组合预览

修改权重、添加词条或切换任务后，点击「生成组合」刷新右侧预览。计算在后台进行，修改配置会取消旧计算；保存和开始任务均使用当前编辑值，无需等待预览。

每档按 24 张分页，只为符合门槛的组合创建卡片。翻页保留勾选；「全选当前可见」和「取消当前可见」作用于当前词数页签下所有符合门槛的组合，包括尚未翻到的页。底部计数也只统计该页签：组合共计是完整组合数，符合门槛（勾选必带时显示“符合条件”）是筛选后总数，已勾选是筛选后选中数。全选后已勾选等于符合门槛，取消后为 0。

界面没有「最少有效种类」设置；载入存档时会将该限制置 0（关闭）。筛选使用词条单价、档位门槛和组合勾选；命令行配置仍兼容旧字段。

主属性屏蔽优先于词条单价：1 号自动排除生命值、2 号排除攻击力、3 号排除防御力；4–6 号主属性支持多选，也可选「不限」。单选时排除同名副词条；多选时保留能出现在另一种主属性盘上的副词条，并排除所有所选主属性都不可能对应的组合。排除只作用于组合生成和运行判定，单价表与任务存档始终保留原单价。固定值与百分比是不同词条，排除生命值不会同时排除生命值%。载入存档会保留全部合法主属性选择。

保存不依赖生成组合。任务未生成时显示“未生成”并跳过执行；生成后的选中组合保存为白名单，空白名单也是有效配置，不回退到权重接受。切换任务会提交当前编辑内容，任务链中之前的任务依然参与运行，各自的权重、门槛、额度和组合勾选独立。修改后须保存任务存档才会落盘。

### 应用到所有任务

词条单价、当前任务限制和游戏内筛选的套装各有一个「应用于所有任务」按钮，把当前这一项**复制**给任务链里此刻已经存在的每个任务。

- 只铺当时已有的任务：之后新建的任务拿自己的默认值，不会被这次应用绑住，也不跟着改。
- 一次只铺它自己那一项：铺单价不动额度、套装和门槛，反之亦然。
- 只改内存里的任务链，仍需顶部「保存」才写进任务 YAML。
- 任务链为空时按钮置灰。套装依然点「选择套装」开弹窗勾选，勾完只改当前任务。

### 用户配置放在哪

全部用户配置放在公共根目录的 `user/` 下，不放 AppData，也不随新版程序打包；`user/plan/` 保存任务 YAML，`user/` 里还有上次打开的存档、导航档案、界面布局记忆、日志设置和就绪等待档案。目录结构、更新时保留什么、示例如何投放与导入旧存档，统一见 [任务管理器使用说明](./任务管理器使用说明.md) 第 9 节。

## 2. 进驱动盘后的筛选顺序

能按键就按键，不扫关闭按钮。

1. 点左下筛选漏斗。漏斗是**开/关切换**：面板本来就开着时第一下会把它关掉，因此程序点完会找「重置」，读不到就**再点一次漏斗**开回来（最多试 4 次 = 首次 + 最多 3 次补点）；试满 4 次都读不到才中断整轮。
2. 点「重置」，先清空游戏里上次留下的条件。
3. 在中间「游戏内筛选」里选套装、点部位、必要时选主词条。套装要开弹窗勾选，部位和主词条直接摆在面板上。部位 1–6 单选，右侧卡片和中间栏的单价表都是这一号的策略，换号会换一套。1–3 主词条固定不选；4/5/6 只出游戏里这个号能出的主词条，支持多选。同一任务的多种主词条共用单价、门槛和卡片名单；规则不同则分成独立任务。
4. 根据当前任务右侧初始 3 词、4 词的 **0 级组合**自动设置副属性筛选：选择一组词条，命中数量从最低需要的数量一直勾到 `min(4, 选中的词条数)`。
5. **Esc 关掉筛选面板**，回到驱动盘列表，再开始逐张处理。

关筛选用 Esc，比 OCR 找叉再点快，也不依赖关闭按钮模板。

漏斗按钮在设计坐标下约在 **(149, 930)**。左侧「拆解」按钮所在矩形 **(210, 890)—(460, 990)** 是点击禁区：程序在点击前做一次坐标兜底检查，坐标落在禁区内会拒绝点击并报错，避免误入拆解流程。

预设写法：

```yaml
game_filter:
  sets: ["折枝剑歌"]
  slot: 4
  mainstats: ["暴击伤害"]
```

`sets: []` 和 `mainstats: []` 表示不再添加对应条件。号位始终单选：省略 `slot` 时默认 4 号；兼容旧字段 `slots` 时仅取第一个合法号位，空列表也默认 4 号，不表示所有号位。新配置使用 `slot`；需要处理多个号位时，在 `task_chain` 中为每个号位分别建立任务，各自保存规则和卡片名单。

### 自动副属性筛选

无需手动填写副属性条件。可执行任务以实际选择的初始 3 词 / 4 词 **0 级组合**推导副属性筛选；未生成任务跳过。两个初始词数页签共同决定一组筛选，游戏筛出的所有等级盘仍沿用各自档位的判断和强化逻辑。

游戏统计的是所选词条中出现了几种，数量对整组词条共同生效，不是盘子的总词条数。例如只选双暴（2 个词条）时上限就是 2，数量按钮只有 1、2 可用——超过词条数的数量按钮在游戏里是禁用态、点不动，所以工具按 `最低需要 .. min(4, 词条数)` 勾选。

工具比较不同词条集合，选择覆盖全部目标且理论候选组合数最少的单轮方案。同样的候选范围优先少选词条。该估计不代表仓库里实际盘子数量；筛出的额外组合仍由工具精确判定。所有词条均为真正的游戏副属性，已屏蔽的主属性和「废词条」「未出」占位符不会被点选。

筛选以「0 级要求比高等级宽松」为任务前提，只根据 0 级组合推导，高等级不会另开一轮。若接受全废组合、没有 0 级目标或无法缩小范围，工具不加副属性条件。开始任务时，状态及日志会显示实际使用的词条、命中数量或不加条件的原因。

### 全局标签策略接口

界面配置栏「硬过滤（任务链共用）」组最上面两个勾就是这两个开关：「判断后打上弃置标记」「判断后打上锁定标记」，默认都勾上（＝保持原有行为）。同一组设置也可以直接在任务 YAML 顶层写：

```yaml
labels:
  discard: false
  save: false
```

`discard: false`（取消勾选「判断后打上弃置标记」）**只停发 R**：判为弃置的盘在游戏里不留弃置标记，但判断结果、处理计数、结果清单和统计口径照旧——仍然算被判为弃置。盘处于锁定状态时，仍照旧先按 T 解锁并确认，避免直接 R 的确认弹窗，只是不再按 R；盘没锁就不读标签、不按键。标签读数拿不准时不为一个不发的键停链。摘标记（进强化页前那一步）属于强化流程，不受这个开关影响，照常执行。

`save: true` 时，强化过且最终判定升满保留的盘子，退出强化页后核对等级、品质、词条和原状态：未锁定则按一次 T，已锁定不再按。R/T 按后都只快速检查右下角标签提示，不重读整盘；读不清只重读，仍无法确认就停止，不重复按键。收尾一开始就先退出强化页、回到仓库网格（侧栏仍开着），再读数核对并决定是否按 T；确认成功后才记录标签结果。

`save: false`（取消勾选「判断后打上锁定标记」）关闭保留锁定收尾：不读盘面核对、不按 T，也不记标签输入；仍记录升满保留成功，判断、计数和结果清单不变。原本满级而直接跳过的盘不执行保留收尾。旧配置缺这两个标签时按 `true` 处理，界面载入和保存保持这些值。两个开关的界面回显、写回和不发键行为有离线用例覆盖，尚未操作游戏验证。

## 3. 格子上的状态标记（锁定 / 弃置 / 装备）

扫描（看列表）时会读每格右下角的标记：**浅灰圆盘挂锁 = 已锁定**、**红圆牌 = 已弃置**（互斥，不会同时出现）。标记判定用像素阈值，样本与判据见 [识别标定](../技术/识别标定.md)。
识别一律做，**要不要因此跳过由任务存档决定**：

- `skip_locked`（界面「跳过有锁定标记」，默认勾选）/ `skip_discarded`（界面「跳过有弃置标记」，默认不勾）→ 命中就跳过这一格：不点开、不读词条、不占处理计数；
- 对应开关关掉 → 该盘照常点开处理；
- 标记拿不准（判据中间带）且该状态配了跳过 → 重拍再看，仍拿不准就**停止整轮**，不会猜。

**非 S 级固定跳过，没有开关**：稀有度由面板「等级03/15」的分母得出（15 = S、12 = A、9 = B），确认是 A/B 就跳过——不强化、不打标、不进强化页。**但它仍会被点开**：格子上虽然画着盘面自带的稀有度小牌，当前代码不读它，扫描只读「等级」数字与锁定 / 弃置标；格子上的「等级」标签不带上限，所以稀有度只有点开后才读得到，非 S 盘照计 1 件处理、照占「本次最多处理 N」的额度。上限读不出（未知）时按不跳过处理，宁可不跳，也不误丢好盘；A/B 上限的 12 / 9 仍缺真机样本，见 [识别标定](../技术/识别标定.md)。

**满级盘（等级 15）在扫描阶段直接跳过**，不点开、不占额度。该行为由存档字段 `skip_max_level` 控制，缺省为开启；界面没有对应控件，界面保存也不会写回这个字段。

**装备（格子右上角圆形角色头像）当前不判断**：判据缺独立答案卷、识别不准，已暂时停用（扫描不再看头像，因此实际运行时装备盘与普通盘一样处理；`skip_equipped` 字段、界面控件与存档值保留，界面标注「跳过已装备（无法跳过）」）。唯一例外是「试判」页签：那里手工勾选「已装备」并按该开关判断，只影响这次本地试判，不代表运行路径会跳过装备盘。判据与停用方式见 [识别标定](../技术/识别标定.md)，画面元素含义见 [页面识别](../技术/页面识别.md)。

## 4. 套装展示

当前界面用按名字生成的色块和**完整套装名**，字号自适应到放得下全名；选择时以全名文字区分，不是只显示前两字。界面不加载套装真图。
