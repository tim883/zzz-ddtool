# 项目文档索引

zzz-ddtool 是绝区零驱动盘强化辅助工具：截取游戏客户区画面、OCR 读取盘面、按任务规则逐档强化或打弃置标签，不分解驱动盘，不读游戏内存、不修改游戏文件、不抓包。

这里是本仓库公开文档的唯一入口。每篇文档只在自己的分工范围内维护正文，其他位置只留交叉引用。

## 2. 文档与资料分工

- **`docs/` 是公开的现行文档。** 只写当前功能、现行行为、必要数据、用法与当前限制；行为改变时直接更新正文，不保留旧版本对照。公开文档只维护这一套，不需要给用户另配一份图库：同一张图同时用于用户讲解、开发和测试时共用同一路径，不复制维护两份。
- **`../dev-docs/`（源码根同级的本地开发资料目录，不随公开仓库提交）** 保存改造 Spec、Plan、审查与过程记录：某个改造准备改什么、为什么改、做到哪一步、当轮证据是什么。
- 功能完成后，把现行知识整理进 `docs/` 对应分工的文件；过程记录与历史证据默认舍弃，不随公开文档长期维护。
- 命名与入口分工：本文件是唯一综合索引；`使用/` 面向操作工具的读者，`技术/` 面向源码实现。规则集中维护在 [游戏规则](./游戏规则.md)，页面与技术文档用规则编号引用，避免多份文档对同一前提各自改写。

## 3. 模板、样本与记录约定

- **生产模板**在 `src/zzz_ddtool/assets/`，是程序运行时实际加载的识别资源，属于运行资源而非文档素材；讲解模板时直接引用该路径下的文件，不复制副本。
- **有效测试样本**在 `tests/fixtures/`，是回归与标定使用的固定输入，缺失或无法加载必须失败。
- 公开文档不维护第二套参考图库：需要说明画面时用文字描述，或直接引用上述模板与样本。
- **规则已确认、代码已实现、离线测试通过、真机操作通过分别记录，不互相替代。** 同一项功能可以同时处于不同状态，写清当前状态即可，不用其中一个结论代替另一个；**未实施的设计不能写成现有功能。**
