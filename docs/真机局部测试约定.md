# 真机局部测试约定

在源码根**同级的临时测试目录**里放**老大指定的真机局部测试**。独立于生产代码，测完整体删除。

## 一句话定义

不是「另写一套游戏脚本」，而是**从生产链路里把一段切出来单独跑，条件只补到刚够点火**。

## 基本形态

- **复制**涉及的那段代码到该临时目录，在副本上放松触发条件。
- 副本**调用生产方法**驱动控制流，**不重抄按键逻辑**。
  - 反例：把 `_finish_kept_upgrade` 整段抄过来再抄一遍 `press_key_once(VK_T)` —— 那是赝品，测的不是生产代码。
  - 正例：副本里放 `MAX_LEVEL = 3` 这类松条件，把控制流引到生产方法 `_finish_kept_upgrade` 上去。

## 条件改动边界

- 改多少不限（常量、判定、参数都行）。
- 唯一底线：**测完改回去或删掉，生产源码零影响。**
- 副本里改了哪些条件，必须写清楚。

## 执行粒度

- 游戏停在**强化页**（或该动作对应的界面）。
- 让这段动作**走一次**。
- **看日志时间戳**读耗时，不靠掐表、不跑整个任务。

## 工作协议

1. 老大提出测试意图（如「单独验保留动作正不正常」，意图可能是看耗时）。
2. 我定位该动作在原代码**哪些场景会出现**，给出场景清单。
3. 老大指出确切场景，或说「都测」。
4. 我拿出**最小改动的真机局部测试代码**，满足原代码链路，尽可能少改条件。
5. 跑，报告：测了什么、动了哪些条件、观察到什么。
6. 测完还原/删除，生产源码保持干净。

## 规矩

- **老大要求优先，规范是参考，不是枷锁。**
- 测试期间**不动生产文件**。
- 该临时目录的测试文件与产出，**测完清理**。
- 产出目录仍遵循：独立、不挂在生产文件上的产出放 `D:\WB_agent_out\out`。
