# 识别标定

更新：2026-10-13。

本文记录现行识别判据、颜色与相似度阈值、像素框与区域范围、身份判据、OCR 标定口径，以及套装弹窗的**起始位置**标定。所有标定基于 **1920×1080** 客户区设计坐标；坐标基准与缩放见 [截图与坐标](截图与坐标.md)，页面元素含义与判页边界见 [页面识别](页面识别.md)，点击/滚轮协议与各动作等待取值见 [输入与等待](输入与等待.md)，游戏前提见 [游戏规则](../游戏规则.md)。

图片只引用两类公开文件：生产模板 `src/zzz_ddtool/assets/...`，测试样本 `tests/fixtures/<页面>/...`。

## 布局与坐标基准

- 坐标常量集中放 `src/zzz_ddtool/layout.py`，按 1920×1080 设计坐标写死，运行时按实际客户区尺寸缩放。
- 格子网格：`GRID_ORIGIN=(166,267)`、`GRID_STEP=(135,175)`，9 列 × 4 行，格子中心 `(cx,cy) = (166+c*135, 267+r*175)`。
- 1920×1080 是唯一有标定依据的档位。盘面快路径只接受该尺寸（`discocr.CLIENT_SIZE`），其他尺寸直接拒绝并回退 legacy 整帧解析；套装弹窗的标定布局只在客户区为 1920×1080 时启用，其他尺寸走 legacy 套装点名。
- 套装弹窗布局 `1920x1080-v8`（`gamefilter._calibrated_layout`，与静态清单 `tests/fixtures/filter-replay/manifest.json` 同值）：列表区 `list_area=(800,340,1490,840)`、确认区 `confirm_area=(1040,838,1260,900)`、滚动落点 `(960,540)`、`scroll_wait_ms=600`、`click_wait_ms=400`、`confirm_wait_ms=500`。

## 起始位置标定

套装弹窗的起始位置模式固定为 `origin_mode: reopen_top`：每次在筛选面板点开「点击选择」条，列表都从顶部开始，因此运行时不额外滚动回顶（`top_wheel_events=0`、`top_delta_units=0`）。

- **适用范围**：只对 1920×1080 客户区与布局 `1920x1080-v8` 生效。`SetPickerLayout` 只接受 `reopen_top` 与 `wheel_top` 两种取值；`reopen_top` 时两个回顶字段必须为 0，否则布局判为非法（`filter_replay.validate_layout`）。
- **顶部判据**：首行瓦片上沿条带 `(830,366,1470,384)` 的亮尾（区域内最亮 5% 像素的平均亮度）≤ 120 判「在顶部」，≥ 180 判「已滚动」，两者之间为未知。
- **观察口径**：学习路径打开弹窗后做一次有限的顶部/布局观察；结果未知时共拍 3 张（含第一张）、追加帧间隔 50 ms，仍不是「在顶部」即停止本轮——不做兼容性回顶。
- **回放口径**：缓存回放只按起始模式执行记录在路径里的回顶事件，不判读页面；`reopen_top` 下回放不发回顶事件。
- **样本**：`tests/fixtures/驱动盘筛选/套装弹窗-顶部.png`（列表停在同一屏顶部）、`tests/fixtures/驱动盘筛选/套装弹窗-三行翻页-顶部.png`、`tests/fixtures/驱动盘筛选/套装弹窗-选择段2-前.png`（已滚动，判 False）。关闭弹窗后重新点开、或从底部向上滚到边界，都会回到同一屏顶部。
- 弹窗内没有可见滚动条：顶部与滚动位置只能用上面的像素判据和可见内容判断，不使用滑块，与仓库位置/端点恢复同一口径。

### 静态外观

- 弹窗：标题「套装筛选」、提示行「所选套装的驱动盘均会展示在列表中」、4 列 × 3 行套装格子、底部「重置 / 确认筛选」。样本 `tests/fixtures/驱动盘筛选/套装弹窗-顶部.png`、`套装弹窗-选择段1-前.png`（首屏 12 个套装全部未选中；计数非 0 的格子为可用态，计数 0 的格子带锁形标记）。
- **选中外观**：格子右上角出现绿色对勾，左栏从「EMPTY」变为该套装的效果说明。这是选中外观；工具不判勾选状态，点击前只校验套装名称身份。样本 `套装弹窗-选择段1-后.png`、`套装弹窗-选择段2-后.png`。
- **生效外观**：确认后弹窗关闭，右侧筛选面板保留已选套装的「套装名-【主属性】×件数」行。样本 `套装弹窗-确认后.png`。
- **状态按钮**：选中呈蓝色，未选是普通外观，灰色表示当前筛选条件下不存在该状态的盘，属正常无可点状态（[G01](../游戏规则.md)）；多个状态同时选中取并集，不是「必须同时具备」（[G02](../游戏规则.md)）。颜色识别必须区分普通未选、不可用与看不清的未知，不能把 OCR 丢字当成「无候选」。工具当前不识别状态按钮、也不据此做决策：状态筛选与动态列表的改造尚未实施，成员退出按 [G06](../游戏规则.md) 记账。

### 名称带几何

`_picker_name_bands` 用列表区粗 OCR 的行几何只定位行高，再在四列固定中心逐带认名（最多三行 × 四列 = 十二带）：

- 列中心 `_PICKER_COLUMN_CENTERS = (900, 1064, 1228, 1392)`，每列左右各 74 px。
- 搜索范围取 `list_area` 与 `x 800—1490, y 354—827` 的交集。
- 种子行：文本含 ≥ 2 个汉字、行高满足 `0 < bottom−top ≤ 40`、行框完整落在某列中心 ±74 内且落在搜索范围内。
- 行聚类：相邻种子行中心 y 相差 ≤ 12 归为同一行。
- 行过滤：整行上下各留 4 px 后必须仍在搜索范围内；由该行生成的名称带高度（含上下各 4 px）不得超过 48 px。
- 行数超过三行时抛错停止（名称行几何存在歧义），不任取前三行。
- 滚动位置不是行对齐：滚一次后顶行可能被截断，名称完整视口为 y=354—827。样本 `tests/fixtures/驱动盘筛选/套装弹窗-选择段2-前.png`、`套装弹窗-滚动边缘四行.png`（前三行名称完整、底部被裁切，残行先排除）。
- 生产滚动一次只发送一条 `delta=-8` 的滚轮事件（原始单位 -960），本机实测约移动 447 px、行距约 150 px，即约三行；底部饱和时保留重叠行。样本 `tests/fixtures/驱动盘筛选/套装弹窗-三行翻页-顶部.png`、`套装弹窗-三行翻页-中部.png`、`套装弹窗-三行翻页-底部.png`。

### 名称读取顺序

1. 名称带先走本地图片模板 `picker_names.classify`：ROI 按带四周外扩 8 px，用 `cv2.matchTemplate`（`TM_CCOEFF_NORMED`）；相关度 ≥ 该模板 `match_min_score`（清单现值 0.98）且与次优名称分差 ≥ `match_min_gap`（0.03）才认定。命中即可靠认定，模板在客户区的位置就是点击框与身份框。
2. 未命中/歧义的带整批送名称带 OCR `read_name_bands`：保持原尺寸与真实字符框，仅去色度（转灰度再转回三通道）后送识别网络。返回文本必须匹配 `([\u3400-\u9fff]+)(?:×?[0-9]+)?`，字符框必须落在输入带内且与非目标字符框无正面积交叠，否则该带返回 None。
3. 逐字符框按引擎给出的单行阅读顺序使用，不按 `top` 重排、不跨行拼接。样本 `tests/fixtures/驱动盘筛选/套装弹窗-震星迪斯科候选漏字.png`：「星」的 `top=739` 而「迪 / 斯 / 科」为 738，按 `top` 排序会错拼；该格名称另外需要按名称带重读一次才能隔离。
4. 近似命中但未精确隔离时不点击：间隔 50 ms 重拍新帧重读，认对一次即用；上限 5 次仍不精确才停止（`_PICKER_NAME_READ_ATTEMPTS=5`）。
5. **件数不进入名称指纹**：件数后缀语法为可选的「×」加阿拉伯数字（`(?:×)?[0-9]+`），件数变化不改变身份。样本 `tests/fixtures/驱动盘筛选/裁剪/名称件数-3-合成.png`（名称隔离仍成功）、`裁剪/身份-件数变化-合成.png`（身份仍 True）。
6. **模板资产**：`src/zzz_ddtool/assets/picker/templates.json` 与同目录 `templates/*.png`。底图只裁名称字区，尺寸按字数固定（3 字 60×26、4 字 78×26、5 字 96×26、6 字 113×26，高均 26 px）；清单条目按名字配对，同一名字可以有多条不同渲染样式的变体。资产缺失或损坏时整轮回落名称带 OCR，不阻断点选。

### 名称隔离与身份指纹

- `read_name_span` 只接受两种完整文本：归一化后等于目标名，或等于目标名 + 件数后缀；目标字符必须唯一、连续、与框一一对应。对目标字符框并集取外接矩形（左/上向下取整，右/下向上取整），与非目标字符框不得有正面积交叠，否则返回 None。
- `make_identity` 的裁剪范围就是 `read_name_span` 返回的精确名称范围，不外扩。前景判据：阈值 = p95 − 6，并要求 p95 与中位亮度差 ≥ 12，否则视为「没有可判文字」（空掩码 → 未知）；前景占比必须在 0.02—0.60 之间，超出则指纹生成失败。
- `identity_matches` 在 ±1 px 平移容差内取最好 IoU：≥ 0.60 判 True，≤ 0.45 判 False，两者之间为 None（未知）。
- **低对比度行**：名称文字画在与字形等大的浅灰底板上（底板中位亮度约 95、字亮部约 128），判据只保留最亮的文字核心。样本 `tests/fixtures/驱动盘筛选/套装弹窗-低对比度-未选.png` 与 `套装弹窗-低对比度-已选.png`（已选时绿勾在名称框之外，身份仍需匹配）；派生样本 `裁剪/身份-低对比度-件数变化-合成.png`（True）、`裁剪/身份-低对比度-换名-合成.png`（False）、`裁剪/身份-低对比度-遮挡-合成.png`（None）、`裁剪/身份-低对比度-亮度变化-合成.png`（名称范围像素整体 ×1.3、结构不变，仍 True）。
- **目标匹配** `_match_targets`：完全相等 `(3, 1.0)` ＞ 包含 `(2, 名字占整条文本的比例)` ＞ 相似 `(1, ratio)`，相似度下限 `_PICKER_MATCH_CUTOFF = 0.75`；两个不同框的最高得分元组相等、或两个目标命中同一文字框时返回 None（冲突即停止，不猜）。主属性/词条点名用同一 0.75 下限；副词条名解析到副词条表用 0.55。
- **点击前检查**：`_pre_click_state` 只校验名称身份，帧内不判勾选；任何点击之前，本帧全部候选的名称框与身份指纹必须全部就绪，框重叠或指纹生成失败立即抛错停止。
- **拒绝取证**：DEBUG 下把导致拒绝的同一原帧与名称框存进本轮 `diagnostics/picker-failures/`，不追加截图，保存失败不覆盖原故障。样本 `tests/fixtures/驱动盘筛选/套装回放-滚动中拒绝原帧-20261012.png` 与 `套装回放-滚动稳定失败后-20261012.png`：同一个名称框在滚动未停的帧上 IoU 落到下限以下、在稳定帧上匹配，因此缓存坐标回放途中不判读图像。
- 冲突与失败口径：识别不出、隔离不出精确文字框、指纹生成失败都停止本轮，不通过继续滚动绕过。

### 勾选判读已取消

- 现行口径：点击套装前只校验名称身份与窗口绑定，点击后不复核勾选。旧的颜色计数勾区判据（按列中心偏移取固定区域、绿色像素三态）已删除，相关样本保留：`tests/fixtures/驱动盘筛选/套装弹窗-激素朋克未选-绿色图案.png`（盘面绿色图案曾落进旧勾区）、`套装弹窗-两项选中第三项未选-20261012.png`（旧计数命中数为 0 的失败帧）。
- 0 件、灰色带锁图标的套装仍会照常点击并保留在路径目标里（[G10](../游戏规则.md)）：不按亮度或件数拒绝点击，不删路径目标，也不因此提前结束任务。

### 确认按钮

- 确认区 `(1040,838,1260,900)` 只读一次：精确匹配「确认筛选」必须恰好命中一处，再隔离文字框、点文字框中心；按钮文字框同样生成身份指纹。
- 点击前状态 `_confirm_ready`：身份与可用都必须是 True；任一项明确不符（False）优先，未知返回 None（不点）。可用判据 `_picker_enabled` 取按钮区与其紧邻框的亮尾（最亮 5% 均值），≥ 180 判可用，灰暗保持未知。
- 合成样本：`tests/fixtures/驱动盘筛选/裁剪/确认按钮-换名-合成.png`（同帧「重置」的文字贴到按钮位置 → False）、`裁剪/确认按钮-遮挡-合成.png`（用按钮底色盖住文字 → None）。
- 点击后弹窗必须关闭、右侧面板必须仍在，否则停止；关闭判据是提示行三态，观察最多 3 帧。
- 关弹窗必须且只能点「确认筛选」，不按 Esc 绕过：Esc 会取消已勾选的套装。
- 缓存回放中确认按钮已有坐标时直接点击，只核对窗口绑定；点击后的弹窗关闭与面板存在检查保留。

## 副属性筛选面板与连续选项点击

- 就位判读 `_inspect_substat_targets`：范围限定在「副属性词条」标题下方、右侧面板 `(1300,100,1880,980)` 之内；命中语义复用 `_normalize_stat` 与 `_count_value`，同名或同数量的重复命中按歧义处理，不取第一个。
- 就位三态：任一已确认目标的文字框底边 > `height − 160` → False（压在面板底部点击无效带上）；缺目标或有歧义 → None；全部目标唯一可见且都在可点击区 → True。颜色是否选中不参与就位判读。
- 数量按钮按 1—4 全量清单判就位：低于筛选下限的数量也要能取消，缺任何一个都算未就位。实际点击只对 `1..min(4, 已选词条数)` 生效——超过词条数的数量按钮在游戏里是禁用态。
- **底部点击无效带**：面板最下方有一条固定高度的无效带，落在其中的点击游戏完全不响应（不是坐标 bug）。面板内任何要点的东西，底边低于 `height − 160` 时必须先滚动把它顶上来再点。面板一次滑到底连发 8 条滚轮事件、落点 `(1560,500)`，中途不抓图、不重复定位光标。
- 副属性区未展开时先一次滑到底再定位「点击展开」开关，返回展开后的那一帧供后续点名复用，省掉一次面板 OCR。
- **连续点击**：全部目标在就位的同一帧上决定；组内释放后等待 0，且不插截图、OCR 或选中态复核；全部实际点击结束后统一检查所有目标的蓝色选中态，末尾首帧仍是旧态时最多观察 3 张新帧、追加帧间隔 50 ms，不重复点击、不重做面板 OCR；耗尽仍失败才停止。无点击时复用已满足的初始帧，不额外等待。各动作的等待取值见 [输入与等待](输入与等待.md)。
- **蓝色选中判据** `_option_selected`：采样文字框周围背景（左右各留 `max(4, 14×宽/1920)` 像素），蓝通道 > 110 且蓝 > 红 + 45、绿 > 红 + 25 的像素占比 > 0.15 判选中。样本 `tests/fixtures/驱动盘筛选/副属性-攻击百分比误报失败后-20261012.png`（点击后立刻抓帧仍是旧态而误报失败，稍后同一按钮已蓝色选中）。
- **外观样本**：`tests/fixtures/驱动盘筛选/副属性-展开未就位.png`（刚展开、面板未滚动，只露出 生命值 / 生命值百分比 / 攻击力 / 攻击力百分比，其余属性与数量按钮在可视区之外，属「目标缺失」态）、`副属性-展开已就位.png`（面板滑到底，全部属性与数量按钮 1 / 2 / 3 / 4 都在可视区内可点击）。
- 主属性词条区默认收起，展开开关取标题正下方的「点击展开 / 点击收起」行；标题露出但开关被裁在视口底部之外时继续滚动重读，滚满 8 轮仍不就位才中断。主属性选项在「主属性词条」与「副属性词条」两个标题夹定的纵向区间内点名（各自的标题中心再留 20 px 边距），打分同样是全等 ＞ 包含 ＞ 相似度（下限 0.75）。
- 预设写法与游戏 UI 的归一化：`%` 与 `％` 一律写成「百分比」（`攻击力%` → `攻击力百分比`），否则永远认不上。
- 主属性路径只抓一帧：`_open_mainstat_section` 把展开后的那一帧交给 `_pick_mainstats` 复用（两者之间没有点击，帧不会变）；展开成功与否不再回读校验。

## 套装路径学习与回放

- **生产链**：`Runner._run` → `_run_job` → `gamefilter.apply_game_filter` → `apply_sets_mainstats` → `_select_sets_with_replay`，按 legacy / learn / replay 三种模式分派。每个新任务仍完整重置筛选，依次设置号位、套装、主属性、副属性。`FilterReplaySession` 每次任务链新建、同一链共享，结束/停止/失败时清空 routes，不跨运行保存。
- **缓存键** `SetPickerKey` = hwnd、pid、width、height、dpi、layout_id 与归一化目标集合 names（去首尾空白、非空、去重、排序）。hwnd/pid/尺寸/DPI 任一变化先清空会话路径，不复用旧坐标；坐标不从其他尺寸缩放。
- **学习**：只对未缓存的名称带做模板/OCR 识别；本屏已缓存的名称带跳过识别，由粗读提供行几何。任何点击之前，本帧全部候选的名称框与身份指纹必须全部就绪。
- **混合执行**：存在新增套装时按视口扫图，只匹配未缓存目标，把新增识别坐标与本屏缓存坐标合并后连续点完；缓存及混合执行只检查暂停、停止与窗口绑定（句柄、进程、客户区尺寸、DPI）。
- **回放**：按路径记录的滚动与点击执行，零名称查找 OCR；失败立即把该路径移出会话。缓存坐标输入只核对窗口绑定，不截图、不判读游戏页面；每个底层输入检查点仍处理暂停与停止，绑定变化立即停止。
- **完全命中缓存**时不发名称识别（目标集合与窗口键都相同才会命中）；确认按钮已有缓存坐标时直接点击，最后弹窗关闭与面板存在检查保留。
- 学习、回放、回顶与 legacy 套装滚动共用同一滚动预算，避免坐标基准不一致；取值见 [输入与等待](输入与等待.md)。legacy 分支一次滚动用 `wheel_client` 默认 `delta=-3`（一条 -360 原始事件），本机实测约 200 px、约 1.3 行；分方向的是原始事件符号，事件数按实际发出为准。
- 学习路径最多滚动 8 轮（`_PICKER_MAX_ROUNDS`），滚满仍未找全全部目标即停止；不把旧路径的成功当作缓存回放的验收。
- 每次套装调用在成功、失败、停止退出时输出 `set_picker_metrics=`，字段为 mode、success、search_ocr_calls、verification_frames、wheel_events、selection_clicks、elapsed_ms。

## 格子上的识别标记

### 弃置标与锁标

- **弃置标**（格子右下角红色圆牌）：纯红 `RGB(203,0,0)`。判据 `equipped.tile_has_discard_badge` 扫 `cx+20..cx+50, cy+15..cy+45`，`R>150 且 G<30 且 B<30` 的像素数 ≥ 50 判有（实测有标 ≥ 245、无标 0），0 判没有，1~49 判「拿不准」。
- **锁标**（格子右下角浅灰圆盘 + 黑色挂锁）：圆盘 `RGB(194,194,194)`，直径约 26 px，圆心同样约 `(dx=+41, dy=+28)`。判据 `equipped.tile_has_lock_badge` 扫 `cx+24..cx+61, cy+12..cy+47`，数「接近 194 的中性灰」（`|r−194| ≤ 22`、`|r−g| ≤ 12`、`|g−b| ≤ 12`）：≥ 120 判有（实测 297~373）、≤ 60 判没有（实测 20~34）、61~119 判「拿不准」。样本 `tests/fixtures/驱动盘仓库/列表与侧栏.png`。
- 两种标记共用右下角同一个槽位（`equipped.py` 注释里红牌记作约 16×16、圆心偏移约 `(dx=+34, dy=+28)`，锁标按同一槽位标定），颜色判据必须分开，红盘不能被算成锁标。
- **拿不准的处理**：只在「该状态配了跳过」时当作问题——重拍最多 `max(1, ocr_retry)` 帧，仍拿不准就停止整轮；没配跳过的状态拿不准不阻塞，盘照常点开、状态在点开后读。
- **空位占位**（`equipped.tile_is_empty`）：只采样格位图标区 x∈[cx−58, cx+58]、y∈[cy−52, cy+50]，步长 3。彩色像素占比 ≤ 0.02 且亮像素占比 ≤ 0.10 判「确认空位」，任一达到 0.04 / 0.20 判「确认有盘」，两者之间为拿不准。彩色 = `max−min > 60 且 max > 70`，亮 = `max > 90`。实测占位格两项均为 0%，有盘格为 6~10% / 30~37%。
- 空位判定不看「等级」标签：不能只凭「没 OCR 到等级」宣布空位；视口相位不为 0 或格位越界时一律拿不准，由调用方按失败路径处理（重读耗尽后停链，进度不越过缺口）。满级格子在扫描阶段直接跳过；已装备判据当前停用，装备格照常处理。两者都仍占物理格位，序号不能压缩。

### 等级标签

- 「等级」标签在格子中心下方 87 px（`GRID_LABEL_DY=87`）：OCR 扫标签定位格子时 `格子中心 cy = 标签中心 y − 87`；标签扫描区 `LABEL_SCAN_AREA=(60,80,1330,1020)`。
- 满级 `等级15` 在扫描阶段直接跳过不点（`skip_max_level`，默认开启）。
- 格子上的「等级」标签不带上限，所以稀有度只有点开后从面板读数（见下文「锁定与稀有度」）。

### 已装备头像

格子右上角彩色圆形头像 = 已装备。头像圆心约在格位图标中心 `(cx+42, cy−50)`、半径约 25 px。

- 判据 `equipped.tile_has_portrait`：头像窗口取 `x ∈ [left+78, left+118]`、`y ∈ [top−2, top+38]`（`left`/`top` 为格位方框左上），窗口内「亮（`max(R,G,B) > 130`）且非黄」像素占比 ≥ 0.10，且内圈 `x ∈ [left+90, left+106]`、`y ∈ [top+10, top+26]` 的非黄像素平均亮度 ≥ 48，两条同时成立才算有头像（有头像实测 0.172~0.465 / 内圈 55.9~182.4，无头像 0~0.031 / 内圈 20.3~41.0）。
- 黄色元素必须排除：判据 `_is_status_yellow` = `R>180 且 G>150 且 B<90`，它同时覆盖格位盘面中下部的金色稀有度小牌与黄色装饰角。旧判据（右上角 58%~98% 窗口里「饱和度 > 40」占比 ≥ 0.12）在这批样本上 7/8 漏判，因为窗口只盖住头像左半边又混进盘面立绘。
- 标定样本：`tests/fixtures/驱动盘仓库/裁剪/头像判据-有头像-133401-r0c8.png`、`头像判据-有头像-132833-r0c0.png`、`头像判据-有头像-161653-r1c0.png`、`头像判据-无头像-133401-r3c6.png`（灰色盘面角）、`头像判据-无头像-114200-r1c6.png`（黄色装饰角）、`裁剪/已装备头像格.png`；回归用例 `tests/test_equipped.py::test_portrait_criteria_on_real_tiles`。
- **当前不启用**：该判据只有格位图像一个来源（右侧面板 OCR 读不到「装备 / 代理」字样，没有文字可对账），缺独立答案卷、识别不准，因此扫描阶段不再调用它，装备盘与普通盘一样处理。停用方式是 `runner.SKIP_EQUIPPED_ENABLED = False` 一处常量：`tile_has_portrait`、标定样本、`tests/test_equipped.py` 的用例、YAML 的 `skip_equipped` 字段与界面控件全部原样保留。
- 恢复方法：先用游戏内「已装备」筛选造一份答案卷（仅标定用、不进运行流程）重新标定并复验，再把该常量改回 `True`（一行）。

## 页面路径与识别区域

- 路径：`仓库页 → 点格子 → 详情页 → 点「查看/强化」→ 缩放页 → 点「》」→ 强化页`。
- 先在仓库选中盘 / 详情路径读取并判断；决定强化后进入强化页逐档读取并重新判断。两处识别区域不同，不能混用。弃置只能在详情页（强化页没有 R 按钮）。
- 详情弹层是独立弹层，**不是仓库右侧的选中盘摘要面板**，动作图标与词条位置都不同；不能把详情弹层里缺少「解除锁定」文字推广成仓库侧栏也没有提示。
- 等级当前值与上限分别读取，不能把上限 15 当当前等级；副属性按名称 / 数值配对。
- 锁定与弃置在仓库侧栏与详情路径都按 `T` / `R` 键（`press_key_once`），不点坐标。
- `layout.py` 里的 `WAREHOUSE_*` 与详情页 `DISC_LEVEL` / `SUB_STATS` 必须分开用：仓库右侧摘要面板的坐标比详情页偏下约 150 px，用混了会让 `parse_disc` 读不到副属性并返回 None。

| 用途 | 常量（1920×1080 设计坐标） |
| --- | --- |
| 仓库右侧选中盘 等级 | `WAREHOUSE_DISC_LEVEL=(1460,398,1610,445)` |
| 仓库右侧选中盘 副属性 | `WAREHOUSE_SUB_STATS=(1410,560,1835,765)` |
| 详情页 等级（含上限） | `DISC_LEVEL=(1180,190,1310,250)` |
| 详情页 副属性 | `SUB_STATS=(1160,390,1790,495)` |
| 强化页 等级窄格 | `UPGRADE_LEVEL=(955,528,1050,592)` |
| 强化页 等级整条（退路） | `UPGRADE_LEVEL_BAR=(880,515,1650,592)` |
| 强化页 副属性 | `UPGRADE_SUB_STATS=(883,419,1692,501)` |
| 缩放页 等级 | `ZOOM_LEVEL_AREA=(1150,170,1500,280)`（`runner.py`） |
| 强化页「阶段添加」 | `STAGE_ADD_AREA=(1150,800,1420,940)`（OCR 找文字点中心，`runner.py`） |
| 强化页「升级」 | `UPGRADE_BUTTON_CENTER=(1511,866)`（硬编码中心，不 OCR，`runner.py`） |

> **坑**：强化页副属性比详情页**整体左移约 300 px**。判断挪到强化页就必须换用强化页坐标，用详情页坐标读强化页读出来是空的。
- **强化页等级退路**：先读贴住数字的窄格 `UPGRADE_LEVEL`；窄格读不出（经验条绿填充涨上来盖住数字、整格 0 行）时退回整条 `UPGRADE_LEVEL_BAR`。整条里混着经验票「320/2400」，解析时按「不含 `/` 的纯数字」挑，否则会把经验票读成等级 0。
- **等级解析**：`等级\s*(\d+)\s*(?:/\s*(\d+))?`；等级必须落在 0—15。经验票「320/2400」的排除方式按模块不同：整条 `UPGRADE_LEVEL_BAR` 用 `skip_slash` 挑掉含「/」的行，快路径 `discocr` 用 `"/" not in compact` 拒绝；legacy 窄格的正则允许「/分母」写法，不单独拒绝。
- **满级回退**：满级后游戏把强化界面切成展示态（等级标到右上 `15/15 MAX`、强化按钮消失），强化页专用区域读不到等级，此时回退按详情页坐标读，仍能读出 `level=15`，交决策层走满级收尾。
- `MAIN_STAT` / `WAREHOUSE_MAIN_STAT` 两个常量连同 `ocr.read_mainstat` 已删除：主属性识别全程没有生产调用，决策不依赖它。

## 副属性两列配对

- 副属性是两列：`名字 数值 | 名字 数值`。
- 配对（`ocr._pair_substat_lines`）：**名字** = 含非数字字符（中文），**数值** = 纯数字（可含 `%`）；按 y 聚类成行（相邻行中心差 ≤ 30 视为同一行），行内按 x 排序后取「名字 → 右侧最近的数值」相邻配对，已配走的数值不再复用。
- `SUB_STAT_SPLIT_X=1650` / `UPGRADE_SUB_SPLIT_X=1250` 保留但不再参与切分。
- 名字里的 `+N` 表示强化次数，`rolls = N + 1`；数值只用来判断是否为百分比（区分 攻击力 / 攻击力%）。名字匹配到副词条表用 0.55 相似度下限，并过一遍只针对副词条的 OCR 错字纠正表（`_SUBSTAT_OCR_FIXES`；每条必须是真替换，且不得是主属性名）。
> **坑**：用单一 `split_x` 切分会把第二列的名字当成数值、第一列的数值当成名字，配对全乱。

## 模板匹配判据

- `template.py::match_icon` 用 `cv2.matchTemplate`，相似度阈值默认 `0.82`。
- **匹配步长必须是 2**：OpenCV 默认步长 1，必须用 `result[::2, ::2]` 取回步长 2 的子集。漏掉切片时分数整体偏高，`0.82` 的语义就变了。
- **灰度式逐位对齐**：`(r*299 + g*587 + b*114) // 1000`（BT.601 整数式，向下取整），不要换成 `cv2.cvtColor(..., COLOR_BGR2GRAY)`——系数与取整方式都不同，分数会动。
- 认页锚点（哪些模板参与判页、误判边界）见 [页面识别](页面识别.md)：驱动盘仓库只认「驱动仓库标题」与「拆解」，「驱动盘页签」在选中态会变黄底、分数在 0.81 附近摇摆，不参与认页；红色返回箭头在详情页 / 缩放页同样存在，不能用来判定仓库页；认不出就返回 `unknown`。

## 盘面快路径的识别判据

`discocr.try_read_disc(image, layout=...)` 只从传入的那一帧读数：不截图、不点击、不跨盘缓存；`layout` 只接受 `detail` 与 `upgrade`。

- **前置拒绝**：未启用 → `disabled`；尺寸不是 1920×1080 → `unsupported_size`；资产缺失或不合规 → `invalid_assets`；布局判别不唯一 → `unmatched_layout`。
- **布局判别**只用 `level` 字段：先模板、未命中再对该 ROI 识别；恰好一个候选布局的等级可解析才认定（判别阶段不看置信度）。
- **字段判定顺序**：完整性 → 置信度 → 解析合法性，拒绝原因分别是 `incomplete_fields` / `low_confidence` / `invalid_data`。
- **四个副词条槽**：1—3 槽必须完整；第 4 槽要么完整，要么由空槽证据确认。空槽只认**数值列**有没有墨迹（真实词条的数值必然被渲染，节标题没有数值）：数值列 ROI 最大灰度 < 60（`EMPTY_SLOT_MAX_GRAY`）即认空；若名称列仍读到已知词条名而数值列空，说明是「有词条但数值漏读」，按前部缺槽拒绝，不猜三词盘。
- **模板采用条件**：`cv2.matchTemplate` 相关度 ≥ 该模板的 `match_min_score`、与次优模板分差 ≥ `match_min_gap`、模板墨迹被 ROI 墨迹覆盖 ≥ 0.95（`TEMPLATE_COVERAGE_MIN`）且 ROI 墨迹落在匹配框外 ≤ 0.05（`TEMPLATE_EXTRA_MAX`）。
- 墨迹阈值 `INK_THRESHOLD=60`（灰度 ≥ 60 算有字）。
- 详情布局的 `locked` / `discarded` 必须共用同一个整行 rect；R/T 那一次识别只裁整行一次、只识别一次，强化布局不读状态字段。
- 快路径失败不抛业务异常，返回拒绝原因后由 `ocr.parse_disc` / `ocr.parse_disc_upgrade_page` 在**同一帧**回退 legacy 整帧解析器；识别网络自身抛出的异常原样传播，不折算成拒绝原因。legacy 解析正常返回 None 时才按 `ocr_retry` 重拍，重试耗尽即停止任务链。

## OCR 引擎与性能约束

改这些之前先读：它们是**语义等价**的约束，动了会让识别结果漂移。

- 引擎：`rapidocr` 自带的 PP-OCRv6 small（det 9.5M + rec 20M），离线、不联网；一律先按 ROI 裁剪再识别，不做全图检测——全图会把左侧网格图标也当字认。
- 字符框开关（`return_word_box` / `return_single_char_box`）是引擎实例属性，因此所有走同一引擎的识别都用同一把锁串行化；读名称字符范围时进入前记下开关原值、退出时恢复（含异常路径）。
- OCR 检测边长 `Det.limit_side_len = 160`（默认 736）：`limit_type=min` 只放大不缩小，1920×1080 整屏不会再被放大，直接按原分辨率检测；最短边本来就 ≥ 160 的大区域不受影响；最短边 < 160 的小区域仍会被放大到 160（只是不再撑到默认的 736）。
- `read_rect` 必须先裁后转 BGR（`image.copy(left, top, w, h)` 之后再转），不要转整屏。
- `runner._grab(need_page=False)` 用于只借这一帧图、不关心停在哪一页的调用（强化弹层里按坐标点击等）：弹层不命中任何页模板，逐个跑页模板是白等。真正要判页的调用保持默认 `need_page=True`。
- 准备阶段与正式扫描共用同一份识别结果（`_grab_label_frame`：同一帧只识别一次）；主属性路径只抓一帧（见上文面板一节）。

## 候选复用与定位检查

游戏前提：[G04](../游戏规则.md)（任务按等级降序，强化后当前盘按新等级前移、其他盘相对顺序不变）。

- **复用条件**：缓存绑定任务、筛选签名、客户区尺寸与已确认总数；只有原扫描是等级降序、位置已确认且缓存可用时才启用。正常路径复用首次 / 本批扫描的未处理候选，不再比较已处理区的等级排列。
- **单屏返回**后只确认仓库页面与尺寸，并在 `COUNT_AREA=(60,105,420,175)`（`navigation.py`）读标题数量；不读全网格等级与锁定/弃置标记，不切页、不滚轮。样本 `tests/fixtures/驱动盘仓库/升级前-34件-序号32.png` 与 `升级后-34件-序号28.png`：同一件 0 级盘升到 3 级后由零基序号 32 移到 28，数量仍 34，最后未处理的序号 33 仍是 0 级。
- **长列表恢复**：切页置顶后按保存的顶部行 / 像素相位发送已标定的滚轮协议；置顶布局与目标相位只在第一列 `RECOVERY_COLUMN_AREA=(100,200,230,945)`（`runner.py`）核对等级文字的位置，不解析等级数值、不重建候选。两个区域都是 1920×1080 设计坐标，按客户区尺寸缩放。
- 返回后用确认的视口几何换算缓存坐标；`next_index`、实际处理数、工作批次与扫描批次都不因复用而增加。旧前缀的等级与标记不代表当前库存、也不参与决策，只保留格位几何供下一次正常前进选锚点；未处理候选仍按原状态跳过规则处理。
- 日志区分「复用未处理候选 / 复用列表候选」与「扫描列表」。任务切换清空恢复缓存，签名不符拒绝使用。
- **失败边界**：页面/数量读取不清按 `ocr_retry` 有限复核，定位恢复最多两次；证据不足才进入完整重扫，异常重扫只核对未处理后缀。明确数量变化、后缀变化或恢复耗尽仍停止整条链。
- **已知限制**：没有维护物品 ID，无法仅靠标题数量与位置检测同数量、同外观的外部换位，因此依赖 G04 的其他盘顺序稳定；游戏状态筛选/标签导致成员退出的旧阶段二设计未接入（记账见 [G06](../游戏规则.md)）。

### 恢复路径单帧复用

- `_restore_once` 只抓一帧并读出整幅列表区域 `layout.LABEL_SCAN_AREA=(60,80,1330,1020)`，把该帧与 OCR 行一起返回。页面/尺寸/数量核对（数量取自 `COUNT_AREA`）与列位置简查（列范围 `RECOVERY_COLUMN_AREA`）都用这一份结果：两个区域本就整块落在列表区域内，判据、阈值与结论都不变，只是不再补第二次抓帧与识别——与准备阶段「同一帧只识别一次」的口径一致。
- 不传 `lines` 时两个函数仍各自补读一次原区域，保持单独调用的行为；异常重扫分支 `_scan_cells(state)`、恢复重试次数、判定与候选复用口径均未改动。
- 回归以「给定行时再次识别即断言失败」拒绝回退（`tests/test_runner.py::test_recovery_position_reason_reuses_given_lines`、`test_recovery_summary_reuses_given_lines`），并断言一次恢复尝试只抓一帧（`test_long_recovery_reuses_candidates_and_half_row_position`、`test_cached_recovery_f9_resume_does_not_repeat_top_reset`）。

## 首档复用与单屏末件收尾

- 点中格位后第一次读取侧栏完整盘面并精确判断保留。仅在判为 UPGRADE、确认进入强化页之后，`Runner._upgrade_loop(..., initial_disc=disc)` 首轮复用当前盘数据，省略升级之前的重复等级/词条 OCR；每次真实升级后仍抓新图验证实际等级并重判。没有传 `initial_disc` 时维持先读盘的行为。
- 首轮复用前仍检查暂停/停止：检查点进入时已暂停，恢复后重新读盘；F10 不追加首档输入。
- `_enter_upgrade_page` 的「查看/强化」来自同一帧同一区域，只做一次按钮 OCR。进缩放层改为睡满 `_READY_FLOOR_MS["open_preview"]` 后按硬编码坐标点「》」箭头，原先的 open_preview 就绪轮询与箭头定位已停用；只有 open_upgrade 仍是就绪等待。
- **单屏末件**：单屏本件最终判断、标签与回仓库完成后，只有连续前缀 `next_index` 等于本任务已确认的 `single_screen_total` 时才结束任务，不再恢复下一件候选；尚有候选、未知屏障、未知总数或长页时不走这条捷径。
- 样本：`tests/fixtures/驱动盘详情/首档复用-侧栏盘面.png`（4 号位折枝剑歌、暴击率主属性、序号 2、0 级，四条副词条为 异常精通 / 生命值百分比 / 暴击伤害 / 穿透值）与 `首档复用-强化未升级.png`（同一件 0 级盘进入强化页，尚未进行阶段添加或升级，等级与副词条仍与侧栏一致）。只切换展示页面时首档数据可复用；升级后数据改变，不能继续复用。`tests/test_runner.py::test_archived_first_upgrade_frames_have_same_disc_data` 从两图独立解析并核对初始等级/副词条一致，缺图、损坏或尺寸不符必须失败。
- **升满保留的收尾**：在退出强化页后、任何仓库分页恢复之前核对盘面并锁定；未锁定只按一次 T，已锁定不再按，未知或不一致失败。样本 `tests/fixtures/驱动盘详情/升满保留-初始未锁定.png`（0 级、仓库侧栏未锁定）与 `升满保留-15级未锁定.png`（已升至 15 级，强化页仍显示未锁定）：侧栏文字提示能读出初始锁定为 False，15 级完整盘面图在当前侧栏提示判读里为 None——未知不得自动改成 False，也不拿它直接驱动 T；新收尾先退回侧栏再读标签。

## 锁定与稀有度

### R/T 提示

- 仓库页右下角 `ACTION_ROW=(1600,1000,1880,1070)` 是 R/T **提示文字**，不是图标；该区除 R/T 提示外还可能读到 UID 行，判读只取提示文字本身。
- **快速路径** `ocr.read_action_state_fast`：只裁 `ACTION_TEXT_LINE=(1600,1026,1880,1057)` 这一行（按客户区尺寸缩放）整行送识别网络，不做文字检测、不做方向分类，也不读取副词条。提示会随文字长度横向移动，不能切成固定左右两块。
- **输出条件**：完整提示语法且置信度 ≥ 0.90 才给状态；残缺或低置信一律返回 None。只识别到一侧提示时，另一侧保持 None（调用方不得盲按）。

| 状态 | 面板文字 |
| --- | --- |
| 未锁定、未弃置 | `T 锁定` + `R 弃置` |
| 已锁定 | `T 解除锁定` + `R 弃置` |
| 已弃置 | `T 锁定` + `R 解除弃置` |

- **归属规则**：含「锁定」的行归 T 提示、含「弃置」的行归 R 提示；「解除 / 取消」只在**自己的**提示里生效；被 OCR 拆成单独一行时按与哪组提示同列（横向最近）归属。游戏文案是「**解除**弃置」，「取消弃置」只作为兼容写法保留。
- **未知不等于未标记**：读不到某个提示时返回 None（未知），调用方必须重读，仍未知则停止或拒绝盲按标签键；把读不到当成「没标记」会按 R 把弃置标记反向切换。
- 正常盘面解析仍用整行 OCR 版的 `read_action_state`（`ACTION_ROW` 区域）。
- 样本：`tests/fixtures/驱动盘仓库/列表与侧栏.png`（R 弃置 / T 解除锁定）、`tests/fixtures/驱动盘详情/首档复用-侧栏盘面.png`（R 弃置 / T 锁定）、`tests/fixtures/驱动盘仓库/标签-已弃置.png`（R 解除弃置 / T 锁定）。
- **按键后复核**（`Runner._verify_label`）：只重读新帧、不补按；另一标签意外变化或一直未知即失败停止；锁定盘弃置先按 T 确认解锁再按 R（[G07](../游戏规则.md)）；暂停代次改变才复验核心盘面，常规按键后不重读词条。观察次数与间隔取值见 [输入与等待](输入与等待.md)。

### 稀有度（由等级上限推出）

- 面板显示 `等级03/15`，分母就是上限：`RARITY_BY_MAX_LEVEL = {15:'S', 12:'A', 9:'B'}`。等级与稀有度由同一次 `read_rect` 读出，不额外加 OCR；上限缺失或不在档位时返回 None（未知，不据此跳过）。
- **不猜徽章颜色**：面板等级左边那枚 S 徽章是纯图标，OCR 读不出；格子盘面中下部的金色小牌（大写字母 + `RARITY` 字样）是纯图形，没有模板也没有答案卷，当前代码一律不读。
- **决策**：确认非 S 的盘固定跳过，没有开关（旧 YAML 的 `filters.require_s_rank` 被忽略、不再写回）；稀有度未知（None）按不跳过处理，宁可不跳也不误丢好盘。
- 非 S 盘仍会被点开并计 1 件处理：格子上的「等级」标签不带上限，稀有度只有点开后才读得到。
- 样本 `tests/fixtures/驱动盘详情/详情弹层.png`（S 级 `等级 0 / 15`、生命值主属性、三条副属性）。

## 就绪等待标定

就绪等待的机制、六类 kind 与默认下限 / 超时见 [页面识别](页面识别.md) 第 11 节。本节只记判据与标定口径。

- 稳定规则固定：`poll_ms=50`、连续 **2 帧**状态 key 相同，且已过该 kind 的下限；超时抛 `ReadinessTimeout`，调用方按任务错误处理。
- **下限公式**：`floor = ceil((max(t_stable − t0) + max(20, 2×poll_ms)) / 10) × 10`。稳定帧对取最后一段连续稳定里的**首对相邻帧**（第 1 帧为 `t_ready`、第 2 帧为 `t_stable`），段尾帧不是测点。**假就绪** = 帧对之前出现过 `ready=True` 且 key 不同。
- **本机等待档案** `user/scan-waits.json` 可覆盖各 kind 的下限：档案的环境（machine_id、客户区尺寸、DPI、exe 路径、游戏 build）、schema / predicate 版本或任一字段不合法即整份失效、全部回落到默认下限。释放后等待（动作级与 `return_warehouse` 逐边）的取值与档案规则见 [输入与等待](输入与等待.md)。
- **`material_ready` 素材条描述子**：归一化饱和度 `max(R,G,B) − min(R,G,B)`（按各帧 p85 归一化，整条无彩色返 0），key 为 16 格逐格二值「是否已填充」（`block.mean() ≥ 0.5`）；常量 `_MATERIAL_BAR_CHANGE_THRESHOLD=0.20`、`_MATERIAL_BAR_STABLE_THRESHOLD=0.05`、`_MATERIAL_BAR_FILL_THRESHOLD=0.5`、`_MATERIAL_BAR_MIN_SATURATION=12.0`（`runner.py`），变化阈值必须大于稳定阈值。生产路径已不再调用该等待，常量与探针保留给 `_pick_material` 测试入口。
- **抓帧瞬时无效帧重试**：`capture._CAPTURE_ATTEMPTS=3`、`capture._CAPTURE_RETRY_DELAY_S=0.08`，覆盖点「查看」后约 150—230 ms 的切页过渡黑帧；连续 3 次无效才判定为「真的截不到」。

## 材料返还弹窗判读

- 盘升到满级时，多出来的强化素材会返还并弹出确认框，把强化页整个盖住，等级 / 副属性几个区域都会读 0 行。识别只看标题：去空格后至少一行含 `MATERIAL_REFUND_TITLE = "材料返还"`（游戏文案是「返还」不是「退还」；标题 OCR 实测位于 `(898,404,1021,442)`、置信度 1.00）。
- 确认按钮靠 OCR 找含「确认」的行、点文字中心，不硬编坐标——弹窗高度随返还材料行数变化。
- **调用时机**：只在盘面识别失败之后做一次全窗 OCR 查找（正常路径不付这个代价）。
- **接续口径**：确认为一次输入；确认后从该输入时刻重建第二次 `upgrade_result` 等待，不重发升级。窗口 / 进程 / 尺寸、暂停代次与任务 / 盘面绑定在真实输入检查点上复核，失效即停止，不按旧截图坐标确认；不接续结果等待时只消费同一收尾预算再交回既有有限重试。等待取值见 [输入与等待](输入与等待.md)。
- 升级前的溢出素材状态、弹窗内显示返还材料与「确认」、确认后回到 15 级盘面这三张局部测量样本未随公开仓库提供，本节只保留上述判据；也不能据此推导所有素材配比的返还条件。

## 已知缺口

- A/B 盘的仓库页格位样本仍未采集：`RARITY_BY_MAX_LEVEL` 的 12 / 9 两个上限值未经真机确认。
- 「已装备」只有格位头像判据、没有面板文字可对账，且该判据当前停用。
- 格子上的稀有度小牌没有 S / A / B 三档答案卷，代码一律不读。
- 长列表（多屏）恢复的滚轮协议与候选复用尚未由真机覆盖；单屏路径的候选复用已在存档样本上核对。
- 满级后的强化界面切换与材料返还只有局部样本，各素材配比下的返还条件未逐项验证。
