# 数据来源

更新：2026-11-10。外部数据来源、取数口径与取图地址。这里只记录「到哪取、取到什么算数、什么不能从外部拿」；识别判据与阈值见 [识别标定](./识别标定.md)，页面元素见 [页面识别](./页面识别.md)。

## 1. 站点与入口

`nanoka.cc` 是第三方游戏数据库站，**驱动盘套装名与套装图标以它为准**（用户 2026-11-10 定为本项目的可靠来源）。

| 用途 | 地址 |
| --- | --- |
| 驱动盘套装页（人看） | `https://zzz.nanoka.cc/equipment` |
| 版本清单（机读） | `https://static.nanoka.cc/manifest.json` |
| 指定版本的数据（机读） | `https://static.nanoka.cc/zzz/{latest}/equipment.json` |
| 套装图标（机读） | `https://static.nanoka.cc/assets/zzz/{图标文件名}.webp` |

工具运行期**不访问**本站：程序不联网取数，取数是人工/脚本动作，取回的结果落到仓库文件里（套装名 → `data/sets.json`）。

## 2. 先取版本段

```powershell
(Invoke-WebRequest -Uri 'https://static.nanoka.cc/manifest.json' -UseBasicParsing).Content |
  ConvertFrom-Json | Select-Object -ExpandProperty zzz
```

| 字段 | 用法 |
| --- | --- |
| `zzz.latest` | 当前数据版本段（形如 `3.4.3+20291004`），拼进数据路径。**每次现取，不写死**——站点升版后旧段可能下线 |
| `zzz.new.equipment` | 最近一次版本新增的套装 id 列表，用来判断「有没有新套装」 |
| `zzz.live` | 站点标为线上（live）的版本，通常落后于 `latest`（含未上线/前瞻数据）。本项目按 `latest` 取名字，好提前把新套装准备好 |

## 3. 取套装名

```powershell
$latest = ((Invoke-WebRequest -Uri 'https://static.nanoka.cc/manifest.json' -UseBasicParsing).Content |
  ConvertFrom-Json).zzz.latest
$sets = (Invoke-WebRequest -Uri "https://static.nanoka.cc/zzz/$latest/equipment.json" -UseBasicParsing).Content |
  ConvertFrom-Json
$sets.PSObject.Properties | ForEach-Object { [pscustomobject]@{ id = $_.Name; name = $_.Value.zh.name.Trim() } }
```

`equipment.json` 是以套装 id 为键的对象，驱动盘套装 id 从 `31000` 起、每套 +100（中间有空号，如缺 `31700`、`32000`、`32100`）：

| 字段 | 含义 |
| --- | --- |
| `icon` | 图标在游戏资源里的路径，形如 `UI/Sprite/A1DynamicLoad/IconSuit/UnPacker/SuitWoodpeckerElectro.png`；站点还没出图时为空串 |
| `zh.name` / `en.name` / `ja.name` / `ko.name` | 各语种套装名 |
| `zh.desc2` / `zh.desc4` | 2 件套 / 4 件套效果，带 `<color=#FFFFFF>` 等游戏内标记 |

口径：

1. 名字取 `zh.name`，落地前 `Trim()`——站点个别条目带尾随空格（如 `33700`「雪兔梦游仙境 」）。
2. 站点未做本地化的字段返回占位串（`EquipmentSuit_{id}_name`、`EquipmentSuit_{id}_2_des`）。命中 `^EquipmentSuit_\d+_(?:name|\d+_des)$` 的不能当名字用；新套装常是韩文占位、中文正常。
3. 名字写进 `data/sets.json`，**按拼音序插入**，不追加到末尾（列表本身就是拼音序，追加会打乱界面格子的固定顺序）。`gamedata.SETS` 每次用到时从文件重读，改完即生效、不用重启。
4. 名字进了 `data/sets.json` 后，界面「选择套装」、任务存档与游戏侧筛选目标都认它；游戏内点选靠名称带 OCR 兜底，直到有真机帧补出名称底图（见第 4 节）。
5. 站点只用来**新增或校对套装名**。套装效果文案与数值不进入本工具的任何判定，不抄进 `docs/`。

## 4. 取图：两种图，来源不同

| 图 | 来源 | 用途 |
| --- | --- | --- |
| 套装图标 `Suit*.png` | 本站：`https://static.nanoka.cc/assets/zzz/{图标文件名}.webp` | 可存成 `src/zzz_ddtool/assets/sets/{套装名}.png`。**非必需**：缺图时界面用完整套装名的计算色块（`seticons.paint_set_icon`） |
| 套装名底图 `set-XX.png` | **只能来自真机帧**，站点没有 | `src/zzz_ddtool/assets/picker/templates/` 的名称模板，清单见同目录 `templates.json` |

- 图标地址取 `icon` 字段的**最后一段文件名**、去掉扩展名、换成 `.webp`（站点把游戏内的长路径压平到一层）。`icon` 为空串表示站点还没出图，等站点更新后再取。
- 套装名底图是游戏内套装弹窗的**渲染像素**，站点数据里没有这一层；站点只能告诉你「要认哪几个字」，不能代替底图。缺底图时整轮回落名称带 OCR，不阻断点选。
- 新套装名底图的尺寸按字数固定（3 字 60×26、4 字 78×26、5 字 96×26、6 字 113×26，高均 26 px），只裁名称字区，登记来源帧与 SHA256；资产规范见 [识别标定](./识别标定.md)「套装弹窗判读」的模板资产条目。

## 5. 边界

- 本站是第三方数据源，只承担「套装名 + 套装图标」。它错误或改版时，受影响范围就是一次手动取数，不影响工具运行。
- 真机截图、名称底图、判据阈值仍然以 `tests/fixtures/` 与 `src/zzz_ddtool/assets/` 为准，不用外部站点数据替代。
