# 截图与坐标

## 坐标体系

UI / 网格坐标常量集中在 `src/zzz_ddtool/layout.py`，按 **1920×1080 设计坐标**写死。

- `scale_point(x, y, w, h)` = `(x*w/1920, y*h/1080)`，`scale_rect(...)` 同理
- `ocr.py::read_rect` 内部自动 `scale_rect`（传设计坐标，内部按真实分辨率缩放）
- 点击 `wininput.click_client` 用客户区坐标：`client_to_screen` 转屏幕坐标 → `SetCursorPos` → `mouse_event` 发送
- 缩放口径 = 标准坐标 × (实际宽 / 1920, 实际高 / 1080)，与既有实现保持一致，不自造差异

**一切坐标以窗口客户区为基准，帧就是客户区。** 由此有一条承重不变量：**帧像素 ≡ 客户区像素**——`read_rect` 读出的图像坐标直接就是 `click_client` 要的客户区坐标。原生帧下它恒成立；一旦把帧降采样，帧是 1920 而客户区仍是真实尺寸，所有点击会整体偏 `真实宽 / 1920` 倍。所以**不要为了适配分辨率把帧降采样回 1920**。

### 1920×1080 是唯一实测档位

坐标虽然按比例缩放，但**只有 1920×1080 客户区有标定依据**。换分辨率时的实际状况：

| 层 | 非 1920×1080（16:9）时的行为 |
| --- | --- |
| 设计坐标 → 实际像素 | 按真实宽高折算，正常 |
| 认页（`screen.py`） | 正常 |
| 盘面读取 legacy | 正常（整帧 OCR，按比例缩放矩形） |
| 盘面读取快路径 | **直接拒绝**，退回 legacy |
| 套装筛选生产标定布局 | **不可用**，退回 legacy 套装选择路径 |
| 点击坐标 | **正确**——前提是**保留原生帧** |

**盘面读取快路径为什么拒绝**：`discocr.CLIENT_SIZE = (1920, 1080)`，`try_read_disc` 第一道门即 `(image.width(), image.height()) != CLIENT_SIZE → unsupported_size`；资产侧要求 `profiles.json` 的 `client_size` 必须等于它，模板 PNG 也是 1920 原生尺寸。所以非 1080p 下**必定**回退 `_parse_disc_legacy`，识别成本上去，这不是故障。

**套装筛选同理**：生产标定布局（`SetPickerLayout`，标识 `1920x1080-v8`，含列表区、确认区、起始模式与滚动 / 点击 / 确认等待）只在客户区恰为 1920×1080 时可用（`gamefilter._calibrated_layout` 遇其他尺寸返回 `None`），并额外要求窗口 DPI 可读；否则走 legacy 套装选择路径。

识别与坐标的两套数字（像素级阈值 vs 按比例缩放的矩形）在非 1080p 下会分家，这是当前已知限制。

## DPI

- 窗口 DPI 由 `GetDpiForWindow` 读取（`navigation.window_dpi`）；API 不可用或返回 0 时返回 `None`，**不伪填 96**。
- DPI 与 hwnd、进程 PID、客户区尺寸一起作为窗口绑定键：任一变化会使套装筛选的会话路径作废（`gamefilter._invalidate_session_routes`），不复用旧坐标。
- 需要现标滚轮协议的路径在 DPI 不可读时直接停止，不开始标定。
- 样本记录里出现的 DPI（如 96 / 100%）只是当次采集环境，不是代码常量。

## 找窗口与截图（`capture.py`）

- `find_game_hwnd()`：优先匹配 `exe == ZenlessZoneZero.exe`，标题兜底（含「绝区零」/「ZenlessZoneZero」）。
- `_print_window()`：`PrintWindow(hwnd, PW_CLIENTONLY|PW_RENDERFULLCONTENT)` 截客户区。
- 无效帧判定 `_looks_unusable()`：全黑图，或近似纯色的空白图（PrintWindow 被拒时会抓到白底帧，旧的黑图判据拦不住）。
- `_bitblt_screen()` 兜底：从屏幕 DC 拷客户区，不打开目标进程，因此不受 UIPI 限制（游戏提权运行时 PrintWindow 会被拒）；前提是窗口可见且在最前，由 `_restore_window` 负责。
- 两级取图都拿到无效帧时，等待 `_CAPTURE_RETRY_DELAY_S = 0.08` 秒后重试整条链，连续 `_CAPTURE_ATTEMPTS = 3` 次都无效才判失败——覆盖打开详情后约 150~230ms 的切页过渡黑帧。
- 浮层排除：截图时不把工具自己的悬浮日志窗截进画面污染 OCR。Win10 2004+ / Win11 上浮层用 `WDA_EXCLUDEFROMCAPTURE` 排除在捕获外（画面不闪），老系统上才真正隐藏浮层。
- `_grab_screen_region`（Qt `grabWindow`）**不在生产截图的降级链上**，只被 Qt 截图桥 `capturebridge.py` 调用。

最小化窗口的处理（避免截错窗口）：

- 游戏窗口最小化时 `GetClientRect` 返回 0×0。exe 匹配**不因最小化跳过**，仍记录该窗口；标题兜底则排除 `exe` 含 `python` 的窗口，避免误中一条龙的 python 窗口（客户区尺寸与游戏不同，截出来的图与坐标会全错）。
- `grab_game_image` 在截图前调用 `_restore_window`：窗口不在前台时经 `focus_window` 执行 `ShowWindow(SW_RESTORE)` 并提到前台（最小化时由此恢复）。

**排查截图分辨率异常，第一步查游戏窗口是否最小化 / 被切走。**

## 裁剪基准与坐标口径

- 所有矩形（页面锚点、OCR 区域、点击锚点、禁止区）都写成 1920×1080 **设计坐标**，按实际客户区尺寸缩放到像素后再从客户区帧上裁剪；不直接在像素坐标上写死。
- 裁剪前不缩放、不降采样帧，维持「帧像素 ≡ 客户区像素」。识别阈值与像素框清单见 [识别标定](./识别标定.md)。
- 分辨率低于 1920 的样本图只用于讲解布局，**不能**当作 1920 像素的阈值或像素框标定原图。

## 悬浮日志窗口（`overlay.py`）

纯 ctypes 的 Win32 分层窗口，用于在游戏画面上叠加日志：

- 类名 `ZZZDDToolOverlay`，标题空，`WS_EX_LAYERED|TRANSPARENT|TOOLWINDOW|NOACTIVATE|TOPMOST`；`WS_EX_TRANSPARENT` 加 `WM_NCHITTEST` 返回 `HTTRANSPARENT`，鼠标完全穿透到游戏
- 深色底（`0x202020`）半透明：`SetLayeredWindowAttributes(hwnd, 0, 220, LWA_ALPHA)`；文字白色、透明背景模式，用的是整体 alpha 而不是色键透明
- 消息循环跑在 `daemon=True` 线程；进程退出 → daemon 线程终止 → 窗口随进程销毁。结束任务后窗口消失是正常的，不是 bug
- `DefWindowProcW` 必须设 64 位 `argtypes`，否则消息循环会 `OverflowError` 刷屏
- 捕获侧不认识 overlay，只持有回调（`capture.set_overlay_hooks`）；隐藏 / 恢复由 overlay 模块在建好窗口后注册
