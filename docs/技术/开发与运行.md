# 开发与运行

本文维护开发安装、源码启动、命令行入口与源码阅读顺序。现行规范、功能与文档索引见 [README](../README.md)，开发规则见 [开发规范](../开发规范.md)，测试范围与证据复用见 [测试约定](../测试约定.md)。

## 环境与安装

开发与打包目标 Python **3.13.5**，依赖版本以仓库根的 `requirements-lock.txt` 为准（含 PyInstaller）。窗口依赖 PySide6，图像处理用 OpenCV / NumPy，OCR 用本地 RapidOCR（包名 `rapidocr`，不是旧的 `rapidocr-onnxruntime`，两者 API 不兼容），配置用 YAML。

在仓库根目录执行安装（已有正确的 `.venv` 时不必重建）：

```powershell
uv venv --python 3.13.5 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements-lock.txt "pytest==9.1.1" -e .
```

`.venv` 只供本机使用。先核对 `.venv\Scripts\python.exe --version` 与已装包元数据，再运行源码；解释器、PATH、系统 DPI 和滚轮协议都必须在本机核实，不直接改全局环境。

## 源码与命令行

以下命令都从仓库根目录运行。开发态也可以用 `打开窗口.bat` 启动窗口；分发使用打包后的 exe。

```powershell
.\.venv\Scripts\python.exe -m zzz_ddtool
.\.venv\Scripts\python.exe -m zzz_ddtool --help
.\.venv\Scripts\python.exe -m zzz_ddtool capture
.\.venv\Scripts\python.exe -m zzz_ddtool read-disc
.\.venv\Scripts\python.exe -m zzz_ddtool goto-warehouse
.\.venv\Scripts\python.exe -m zzz_ddtool snapshot-pages
.\.venv\Scripts\python.exe -m zzz_ddtool snapshot-list --config user/plan/example.yaml
.\.venv\Scripts\python.exe -m zzz_ddtool run --config user/plan/example.yaml
.\.venv\Scripts\python.exe -m zzz_ddtool preview --config user/plan/example.yaml
.\.venv\Scripts\python.exe -m zzz_ddtool decide --config user/plan/example.yaml --subs 暴击率,暴击伤害,生命值,防御力 --level 0
```

`goto-warehouse`、`snapshot-pages`、`snapshot-list`、`run` 会进行游戏操作；上面只是用法说明，不要求自动执行。任务 YAML 放公共根目录 `user/plan/`，所有存档地位相同。

F9 暂停 / F10 停止与界面按钮共用同一控制器，在安全检查点与下一次输入动作之前生效：不会等整件盘处理完才响应，也不会在暂停时留下未释放的键。时序与边界见 [输入与等待](输入与等待.md)。

## 日志与打包入口

一轮一个时间戳目录：本轮文本日志是 `log/<时间戳编号>/ddtool.log`，运行截图在同目录的 `captures/`；测试、探测、回放与标定脚本的产物写到 `log_test/` 下的同构目录。目录结构、轮次保留与排查方法见 [日志与截图](./日志与截图.md)。

开发入口（`pytest`、`capture`、`read-disc`、`goto-warehouse`、`snapshot-pages`、`snapshot-list`、`preview`、`decide`、`--start-index` / `--material-slot` 非默认的 `run`、`scripts/` 下的探测与标定脚本）写 `log_test/`；正常 `run` 与界面启动写 `log/`。

打包与发布入口见 [打包与发布](打包与发布.md)：仓库根的 `build.py` 负责打包，`scripts/release.py` 是发布唯一入口。

## 源码阅读顺序

先沿 `cli.py / gui.py → Runner.run → _run_job → _process_cell → _upgrade_loop` 理解一条任务如何执行，再按问题进入以下模块。以下路径相对于仓库根的 `src/zzz_ddtool/`：

1. `cli.py / gui.py`：命令入口、配置编辑和后台线程启动；`config.py / chain.py / taskcards.py`：任务配置、名单与卡片计数。
2. `runner.py`：任务链、配额、逐盘执行、强化收尾及位置恢复；`decide.py / origin.py / patterns.py`：纯判断与三词/四词来源。
3. `nav.py`：页面之间的导航；`navigation.py / traversal.py`：滚轮协议（出厂默认值，启动不标定）、全局位置与端点；`gamefilter.py / filter_replay.py`：筛选和本轮会话路径回放。
4. `capture.py / capturebridge.py / ocr.py / screen.py`：截图、主线程桥接、字段读取和认页；`control.py / hotkeys.py / wininput.py`：控制请求、输入检查点和原生输入。
5. `paths.py / userdata.py / trace.py / stats.py / retain.py`：公共存档位置、迁移、日志、统计和运行截图清理；等待常量、就绪判定与档案在 `actionwait.py / readiness.py`；性能事件与证据核对在 `scanperf.py / runevidence.py`。
6. 仓库根的 `build.py / zzz-ddtool.spec` 负责打包，`scripts/release.py` 负责发布，`scripts/analyze_round.py` 用于逐轮分析。
