# 日志与截图规范

出问题时能回答三件事：**第几步、在哪个页面、当时屏幕上是什么**。

## 一、日志格式

统一「**在哪个页面 · 干了什么 → 结果**」，全中文：

```
15:42:01 [信息] 驱动盘仓库 · 扫描列表 → 成功（第 1 页扫到 9 个盘）
15:42:02 [信息] 详情页   · 点开格子 → 成功（第2行第3列）
15:42:02 [信息] 详情页   · 识别盘面 → 成功（等级3 副词条4条）
15:42:02 [信息] 详情页   · 判断     → 结论（继续强化：分数4.0≥要求3.5）
15:42:03 [错误] 详情页   · 进强化页 → 失败：没找到「查看」按钮  截图=0007-进强化页.png
```

- 页面中文名在 `trace.py::PAGE_NAMES`，动作中文名在 `ACTION_NAMES`
- 认不出的页面/动作**原样输出，不编名字**——编了会误导排查
- 判断类动作结果写「结论」，不写「成功」（"判断 → 成功"读着别扭）

## 二、日志级别决定截图多少

这是标准 `logging` 语义，不是自定义开关：

| 级别 | 截图行为 | 什么时候用 |
|------|----------|-----------|
| `DEBUG` | **每一步都截图** | 排查问题，想看完整过程 |
| `INFO`（默认） | 只记动作，不截图 | 日常跑 |
| `WARNING` | 可疑情况自动截图 | — |
| `ERROR` | 失败必定截图 | — |

用法：

```powershell
py -3.13 -m zzz_ddtool --log-level debug run --config configs/example.yaml
```

`-l debug` 是简写。级别也能在界面上切（调 `logutil.set_level`）。

## 三、截图怎么存

- 目录：`out/captures/<本轮时间戳>/`
- 命名：`0007-进强化页.png`——**前缀就是步骤号，和日志那一行对得上**
- 一轮跑完：
  - 有失败 → 整轮保留
  - 无失败且非 DEBUG → 清理本轮截图，只留日志（截图 1MB+，不清理会撑爆）
  - DEBUG 模式 → 全部保留

## 四、排查流程

1. 打开 `out/logs/ddtool.log`，找 `[错误]` 那行
2. 看行首步骤号，比如 `0007`
3. 去 `out/captures/<时间戳>/0007-*.png` 看当时屏幕
4. 往上翻十几行，看是怎么走到这的

## 五、加新步骤

在 `runner.py` 里调用 `self.trace`：

```python
self.trace.ok("detail", "parse", f"等级{disc.level}")      # 成功
self.trace.fail("detail", "enter_upgrade", "没找到按钮")     # 失败，必截图
self.trace.warn("detail", "parse", "没读出盘面")            # 可疑，截图
self.trace.note("补充说明，不算一步")                        # 注释
```

第一个参数是页面标识，第二个是动作名。都不在映射表里会原样输出，**加新页面/动作时记得去 `trace.py` 补中文名**。
