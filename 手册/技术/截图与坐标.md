# 截图与坐标

## 坐标体系

UI/网格坐标常量集中在 `src/zzz_ddtool/layout.py`，按 **1920×1080 设计坐标**写死。

- `scale_point(x,y,w,h)` = `(x*w/1920, y*h/1080)`，`scale_rect(...)` 同理
- `ocr.py::read_rect` 内部自动 `scale_rect`（传设计坐标，内部按真实分辨率缩放）
- 点击 `wininput.click_client` 用客户区坐标 + `ClientToScreen` 转屏幕坐标

对齐 OneDragon `pc_game_window.py` 的 `get_scaled_game_pos`：标准坐标 × (实际宽/1920, 实际高/1080)。

## 找窗口与截图（`capture.py`）

- `find_game_hwnd()`：优先匹配 `exe == ZenlessZoneZero.exe`，标题兜底（含"绝区零"/"ZenlessZoneZero"）
- `_print_window()`：`PrintWindow(hwnd, PW_CLIENTONLY|PW_RENDERFULLCONTENT)` 截客户区
- 黑图时降级 `_grab_screen_region`（Qt grabWindow）

> **坑**：游戏窗口**最小化**时 `GetClientRect` 返回 0×0，旧逻辑 `if width<64: skip`
> 会把游戏窗口跳过，fallback 到标题匹配，误中 **OneDragon 的 python 窗口**
> （标题"绝区零 一条龙 01"，客户区 1140×760）→ 截图全错、坐标全偏。

已修：exe 匹配不因最小化跳过；标题兜底排除 `exe 含 python`；`grab_game_image` 截图前
`_restore_window`（`IsIconic` 则 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`）。

**排查截图分辨率异常，第一步查游戏窗口是否最小化 / 被切走。**

## 升级流程

页面路径：`仓库页 → 点格子 → 详情页 → 点「查看/强化」→ 缩放页 → 点「》」→ 强化页`。

**首次判断在选中盘 / 详情路径；进入强化页后逐档判断与升级**；**弃置（R）在详情页**（强化页没有 R 按钮）。

`runner.py` 拆成 4 个方法：

- `_enter_upgrade_page(hwnd)`：详情页点「查看/强化」→ 缩放页点「》」→ 强化页（检测「阶段添加」出现即成功）
- `_upgrade_once(hwnd)`：强化页点「阶段添加」→「升级」，升一阶
- `_upgrade_loop(...)`：强化页循环——解析判断 → 判升级就原地升；判弃置 Esc 回详情页按 R；判跳过 Esc 回网格
- `_discard_from_upgrade(hwnd)`：调用 `_esc_back_to_grid` 确认回到仓库侧栏 → 检查控制请求 → 按策略设置弃置标签；侧栏已经是网格，不再额外 Esc

**按当前页面识别结果返回，不以固定 Esc 次数作为执行规则。** 强化 / 缩放弹层与仓库侧栏是不同状态；回到驱动盘仓库即停止回退。仓库侧栏打完弃置后再按 Esc 会退到功能菜单，这是已修过的越界问题，不按旧“三层 Esc”说明重新引入。

> **坑**：旧实现升级完直接 Esc 回网格 + 全量重扫，把强化页当「进一下就退」的跳板，
> 每升一阶都重扫整页。正确做法：升级完**留在强化页原地继续判断**，
> 符合继续升、不符合才 Esc 回详情页弃置。

另一个反复踩的：**强化链路内的 `_grab` 必须禁用自动 Esc**。详情/缩放页会被认成 `unknown`，
`_grab` 一看到 unknown 就按 Esc，结果把自己从仓库页踢回功能页。

还有：`_enter_upgrade_page` 失败时**内部已经 Esc 回网格了**，调用方不要再重复 Esc，
否则多按的那下会把仓库页退到功能页。同理 `max_discs` 截停后**不执行翻页尾巴**——
尾巴上那下 Esc 按在网格上同样会退出仓库。

## 悬浮日志窗口（`overlay.py`）

纯 ctypes 的 Win32 分层窗口（参考 March7thAssistant debug_overlay）。

- 类名 `ZZZDDToolOverlay`，标题空，`WS_EX_LAYERED|TRANSPARENT|TOOLWINDOW|NOACTIVATE|TOPMOST`
- 品红 `RGB(255,0,255)` 色键透明，只显示白字
- 消息循环跑在 `daemon=True` 线程；**进程退出 → daemon 线程终止 → 窗口随进程销毁**，
  所以结束任务窗口就消失了，这是正常的，不是 bug

`DefWindowProcW` 必须设 64 位 `argtypes`，否则消息循环 `OverflowError` 刷屏。
