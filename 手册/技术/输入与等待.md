# 当前输入与等待

核对日期：2026-10-11。本文描述现有代码。新的释放后等待设计仍待实施，入口为 [操作等待提速 Spec](../../dev-docs/功能改造/操作等待提速/Spec.md)。

## 输入函数当前行为

源码为 [wininput.py](../../src/zzz_ddtool/wininput.py)。`pause` 用 `uniform` 选择请求睡眠时间；这些区间是代码常数，未证明是游戏最低需要时间。

| 输入 | 释放/发送之后的当前请求睡眠 |
| --- | --- |
| `click_client` | 普通点击鼠标释放后随机80—180 ms；Alt组合在鼠标释放与Alt释放之间另有40—80 ms，Alt释放后仍随机80—180 ms |
| `wheel_client` | 单条滚轮事件后固定150 ms，再随机80—180 ms |
| `press_key_once` | 最后一组KEYUP后固定30 ms，再随机350—550 ms |
| `press_key` | 现有多通道最后一次WM_KEYUP调用后随机450—650 ms |
| `send_wheel_event` | 单条原始滚轮，零内部收尾等待；调用者管理已标定的事件间隔 |

`focus_window` 每次先执行聚焦并等待200 ms，未成功再执行一轮并等待200 ms；释放前移动/按住间隔也仍存在。当前五类输入返回None，没有真实释放时间的返回接口。

`capture_inputs` 用ContextVar隔离输入观察，真实begin/end共享call_id，共16字段；初始检查点停止时不分配调用ID。输入结束事件在函数收尾等待之后记录，不能把end当作真实释放时刻。

## 业务等待当前行为

[gamefilter.py](../../src/zzz_ddtool/gamefilter.py) 在输入返回后还等待面板打开、重置、选项、滚动和确认。套装v8的layout等待字段为click=400、scroll=600、confirm=500 ms；面板打开550、重置450、号位120、主属性展开700、选项300 ms等固定值也仍执行。这些与输入内部等待是前后叠加关系。

[Runner._wait_ready](../../src/zzz_ddtool/runner.py) 的六类等待从输入函数正常返回后计时；当前默认下限/超时如下，适用的本机等待档案可调整下限。

| kind | 下限ms | 超时ms |
| --- | ---: | ---: |
| select_disc | 500 | 3000 |
| open_preview | 900 | 5000 |
| open_upgrade | 1500 | 8000 |
| material_ready | 600 | 3000 |
| upgrade_result | 1500 | 8000 |
| return_warehouse | 600 | 3000 |

`readiness` 当前predicate_version=1，生产poll=50 ms、连续稳定2帧。返回时刻口径的旧测量不能直接解释为“释放后游戏需要多久”。测量慢探针的下次调度已按抓图时刻计周期，不再在耗满周期后多睡50 ms；探针结束仍复核超时预算。

R/T由 `Runner._verify_label` 快速复核，输入返回后每次先等50 ms，最多 `max(1, preset.ocr_retry)*4` 次。只新帧重读，不补按；另一标签改变或一直未知时失败。弃置锁定盘先T确认解锁再R。返还确认的窗口/进程/尺寸、暂停代次和任务/盘面绑定保护已修复至真实输入检查点。
