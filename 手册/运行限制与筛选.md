# 02 运行限制、游戏筛选、已装备

## 1. 本次最多处理多少盘

配置：`task_chain` 中每个任务的 `max_discs`（新任务默认 100，至少 1）。窗口「当前任务限制」里设置「本次最多处理 N 个盘子」，切换任务会恢复各自的数量。

每个任务独立计数，前一个任务用满额度后继续下一个任务，不会占用后续任务的额度。扫描阶段已经跳过的格位不计数，打开详情处理的盘计 1。

旧配置中未填写任务级 `max_discs` 时，每个任务沿用 `run.max_discs` 作为默认额度；没有任务链的命令行运行仍使用 `run.max_discs`。

到上限后**停在原地，不翻页**——翻页尾巴上那下 Esc 按在网格会把仓库退到功能页。

### 组合预览

修改权重、添加词条或切换任务后，点击「生成组合」刷新右侧预览。计算在后台进行，修改配置会取消旧计算；保存和开始任务均使用当前编辑值，无需等待预览。

每档按 24 张分页，只为符合门槛的组合创建卡片。翻页保留勾选；「全选当前可见」和「取消当前可见」作用于当前词数页签下所有符合门槛的组合，包括尚未翻到的页。底部计数也只统计该页签：组合共计是完整组合数，符合门槛是筛选后总数，已勾选是筛选后选中数。全选后已勾选等于符合门槛，取消后为 0。

客户端不再使用「最少有效种类」，载入旧配置时会将该限制关闭。筛选使用词条单价、档位门槛和组合勾选；命令行配置仍兼容旧字段。

主属性屏蔽优先于词条单价：1 号自动排除生命值、2 号排除攻击力、3 号排除防御力；4–6 号主属性支持多选，也可选「不限」。单选时排除同名副词条；多选时保留能出现在另一种主属性盘上的副词条，并排除所有所选主属性都不可能对应的组合。排除只作用于组合生成和运行判定，单价表与任务存档始终保留原单价。固定值与百分比是不同词条，排除生命值不会同时排除生命值%。载入存档会保留全部合法主属性选择。

保存不依赖生成组合。尚未手动挑卡时，任务按单价与门槛判定；手动挑过卡则保存组合白名单。切换任务会提交当前编辑内容，任务链中之前的任务依然参与运行，各自的权重、门槛、额度和组合勾选独立。修改后须保存任务存档才会落盘。

### 应用到所有任务

词条单价、当前任务限制和游戏内筛选的套装各有一个「应用于所有任务」按钮，把当前这一项**复制**给任务链里此刻已经存在的每个任务。

- 只铺当时已有的任务：之后新建的任务拿自己的默认值，不会被这次应用绑住，也不跟着改。
- 一次只铺它自己那一项：铺单价不动额度、套装和门槛，反之亦然。
- 只改内存里的任务链，仍需顶部「保存」才写进任务 YAML。
- 任务链为空时按钮置灰。套装依然点「选择套装」开弹窗勾选，勾完只改当前任务。

全部用户配置放在公共根目录的 `user/` 下，不放 AppData，也不随新版程序打包：

- `user/plan/`：所有任务 YAML，包括 `example.yaml`、`example3.yaml`。它们和其他存档平等，可正常修改保存。
- `user/last-config.json`、`user/navigation-profile.json`：上次打开的存档和本机导航配置。

根目录由 `.zzz-ddtool-root` 标记；在根目录下任意版本子目录中启动 exe，都会使用这份公共 `user/`。新版只更新程序及运行资源；`data/` 发布内容不再包含 YAML。第一次运行会将旧 `data/` 中的 YAML 导入 `user/plan/`，不覆盖已有文件，原文件保留。同名但内容不同的存档会加导入后缀，保证两份都保留。默认打开/另存目录也是 `user/plan/`；用户主动选择根目录以外的文件时仍可在原位置编辑。

## 2. 进驱动盘后的筛选顺序

能按键就按键，不扫关闭按钮。

1. 点左下筛选漏斗
2. 点「重置」（先清空游戏里上次留下的条件）
3. 在中间「游戏内筛选」里选套装、点部位、必要时选主词条。套装要开弹窗勾选，部位和主词条
   直接摆在面板上。部位 1–6 单选，右侧卡片和左侧权重是这一号的策略，换号会换一套。
   1–3 主词条固定不选；4/5/6 只出游戏里这个号能出的主词条，支持多选。同一任务的多种主词条共用单价、门槛和卡片名单；规则不同则分成独立任务。
4. 根据当前任务右侧初始 3 词、4 词的 **0 级组合**自动设置副属性筛选：选择一组词条，命中数量从最低需要的数量一直勾到 4。
5. **Esc 关掉筛选面板**，回到驱动盘列表，再开始逐张处理

关筛选用 Esc，比 OCR 找叉再点快，也不依赖关闭按钮模板。

漏斗点击：1920×1080 约 **(166, 906)**（白圈）。**(224, 930) 是拆解蓝标，不能点**——
点上去就进拆解流程了。`gamefilter.py::_refuse_dismantle` 会在点击前做一次坐标兜底检查。

预设写法：

```yaml
game_filter:
  sets: ["折枝剑歌"]
  slots: [1, 4]
  mainstats: ["暴击伤害"]
```

空列表 = 重置后不再加条件（游戏里等于不过滤）。

### 自动副属性筛选

无需手动填写副属性条件。未手动挑卡时按当前单价与 0 级门槛分析；手动挑过卡时按组合白名单分析。两个初始词数页签共同决定一组筛选，游戏筛出的所有等级盘仍沿用各自档位的判断和强化逻辑。

游戏统计的是所选词条中出现了几种，数量对整组词条共同生效，不是盘子的总词条数。例如选双暴、数量 2/3/4，就能保留所有双暴盘；只选数量 1 会使补出另一个暴击词条的盘离开列表，因此工具始终补齐最低命中数到 4。

工具比较不同词条集合，选择覆盖全部目标且理论候选组合数最少的单轮方案。同样的候选范围优先少选词条。该估计不代表仓库里实际盘子数量；筛出的额外组合仍由工具精确判定。所有词条均为真正的游戏副属性，已屏蔽的主属性和「废词条」「未出」占位符不会被点选。

筛选以「0 级要求比高等级宽松」为任务前提，只根据 0 级组合推导，高等级不会另开一轮。若接受全废组合、没有 0 级目标或无法缩小范围，工具不加副属性条件。开始任务时，状态及日志会显示实际使用的词条、命中数量或不加条件的原因。

### 全局标签策略接口

默认标签行为照旧。已预留全局配置接口，未来可接高级设置；目前可在任务 YAML 顶层设置：

```yaml
labels:
  discard: false
  save: false
```

`discard: false` 禁止添加和移除弃置标签；判断结果、停止强化和返回仓库的流程仍然执行。`save` 为未来保存标签动作预留开关，目前工具没有新增保存标签动作。界面载入和保存任务存档会保留这两个全局值；旧配置默认均为 `true`。

## 3. 格子右上头像 = 已装备

格子右上角圆形角色头像 → `disc.equipped = True`。硬过滤「跳过已装备」默认开，**不标弃置**。

素材：`手册/素材/已装备-头像格.png`、`手册/素材/筛选-漏斗.png`。

## 4. 套装图标是文字兜底

`assets/sets/` 目前是空的，`seticons.py` 在找不到真图标时会**按套装名算一个色相画色块 + 前两个字**。
39 个套装纯靠色块区分，选的时候容易看串行。想要真图标，把 PNG 按套装名丢进
`src/zzz_ddtool/assets/sets/<套装名>.png` 即可，代码会自动优先用真图。
