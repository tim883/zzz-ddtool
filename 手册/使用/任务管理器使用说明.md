# 驱动盘任务管理器使用说明

适用日期：2026-10-02。本文按当前客户端实现说明，不把计划中的功能当成已有功能。

## 1. 这个窗口叫什么

我建议叫 **驱动盘任务管理器**，简称 **任务管理器**。

它管理的是一整条处理任务链：配置筛选条件、设置词条单价和档位要求、选择组合、保存任务存档，再启动执行。右侧卡片只是当前任务的组合预览，不是全部功能，所以不适合叫“卡片生成器”。

“客户端”可以继续用于区分它和游戏；日常操作时，用“任务管理器”更明确。当前程序窗口标题仍是“驱动盘强化辅助”，本文的名称是命名建议，不代表已经修改了窗口标题。

## 2. 先分清这几个东西

| 名称 | 含义 |
| --- | --- |
| 任务 | 任务链中的一项，有自己的部位、套装、主属性、单价、门槛、组合勾选和处理数量 |
| 任务链 | 左侧列表中的全部任务，按从上到下的顺序执行 |
| 任务存档 | `user/plan/` 下的一份 YAML，保存整条任务链及共用设置 |
| 组合卡片 | 当前任务可能出现的副词条组合，用于查看分数和选择允许的组合，不是仓库里已经识别到的真实盘子 |

`example.yaml`、`example3.yaml` 和其他 YAML 都是普通任务存档。名字里有 `example`，不代表只读、临时或可以在更新时覆盖。

## 3. 最常用的一次操作

1. 点击“打开”选择已有任务存档；或者点击“新建任务”从空任务开始。
2. 在“游戏内筛选”中选择部位、套装和主属性——选完这些，列表里那条任务就显示成“1 │ 4号 · 折枝剑歌 · 暴击伤害”，靠它认任务。
3. 添加需要的副词条，填写单价。
4. 分别设置“初始 3 词”和“初始 4 词”各档的“本档要求”。
5. 设置当前任务最多处理多少个盘子。
6. 点击“生成组合”建立默认勾选名单，按需取消不要的卡片；也可以使用“全任务卡片全选”批量建立名单。显示“未生成”的任务会在执行时跳过。
7. 新建或复制下一项任务，配置完成后调整任务链顺序。
8. 点击“保存”。首次使用或想保留另一套方案时，使用“另存为”。
9. 确认游戏环境和材料，点击“开始任务”。建议先给每项任务设置较小额度，观察实际结果。

打开另一份存档前，先保存当前修改。切换任务会保留编辑内容，但打开另一份存档是在切换整条任务链，不应当把两种操作混为一谈。

## 4. 窗口各区域

三栏之间的分隔条可以拖动调整宽度，但拖不到 0：顶到极限就停在该栏的最小宽度，不会把某一栏藏起来。

### 左侧：任务链

- “新建任务”：创建空任务，不继承前一项的单价和组合勾选。
- “复制任务”：复制当前任务的配置和勾选，再给它独立的新任务身份。没有名字要改，两条内容一样时列表里显示也一样，改完自然分开。
- “上移 / 下移”：改变执行顺序。
- “移除”：删除这项任务，不只是隐藏它。
- 点击列表中的任务：先记录当前编辑内容，再加载选中的任务。

列表里每条任务显示成“序号 │ 部位 · 套装 · 主词条”，**没有单独的任务名要填**。序号用主题色加粗、和正文之间隔一道竖线，是为了跟正文开头的“4号”这类部位号区分开——两者都是数字，连在一起容易看混。序号列固定按两位数字留宽（1 到 9 也占满两位），所以任务超过 9 个时竖线仍然对齐、正文不会左右跳。换套装、改主词条时这一行会立刻跟着变。

条目太长的（例如两个套装加一个长主词条）会在末尾收省略号；点一下选中它，右侧编辑区就是这条任务的完整内容。

同一部位可以有多个任务，例如不同套装或主属性分别设任务。它们的设置是独立的，不是一个部位只能存一套。

### 中间：当前任务的配置

词条单价、游戏内筛选和处理额度都属于当前任务。硬过滤则由整条任务链共用。

5 号位主属性包含“风属性伤害”，可与其他主属性多选，选择随任务存档保存。该属性不属于副词条。

| 设置 | 作用范围 |
| --- | --- |
| 部位、套装、主属性 | 当前任务 |
| 词条单价、各档位要求 | 当前任务 |
| 手工选择的组合 | 当前任务 |
| 本次最多处理多少个盘子 | 当前任务，独立计数 |
| 只要 S 级、跳过锁定、跳过已装备、跳过已有弃置标记 | 整条任务链共用 |

修改当前任务的部位，是修改这项任务，不是自动切换到另一个已有任务。

中间这一栏从上到下是：词条单价、硬过滤、当前任务限制、游戏内筛选。“游戏内筛选”分成两块：上面是套装（点“选择套装”开弹窗勾选），下面是部位 1–6 与主词条。部位和主词条都直接摆在面板上，不再进弹窗；1–3 号位主词条固定，只显示提示，4/5/6 号位才出本部位能出的主词条多选项。词条单价、当前任务限制和套装各带一个“应用于所有任务”，用来把这一项一次铺给任务链里已有的任务（详见第 8 节）。

### 右侧：组合预览与试判

- “初始 3 词”：盘子初始拥有 3 条副词条的升级路径。
- “初始 4 词”：盘子初始拥有 4 条副词条的升级路径。
- `+0 / +3 / +6 / +9 / +12 / +15`：在对应等级检查组合。
- “试判”：手工输入一件盘，检查当前任务会如何判定，不操作游戏。

“初始 3 词”盘升到出现第 4 条后，仍属于初始 3 词的路径，不会因此变成“初始 4 词”任务。

### 底部：状态行与运行日志

状态行显示当前任务链进度和运行状态。下面是运行日志框，点标题行那个箭头可以收起 / 展开：收起后日志窗整个让位，只剩标题行，**窗口跟着变矮一截**（上沿不动，只有底边升上来）；再点一下原样长回去。

## 5. 单价、门槛和主属性

### 单价怎样计算

单价是你给副词条的相对价值，不是游戏中的货币价格，也不是词条实际数值。

每条有效副词条的分数为：

```text
词条分数 = 单价 × (1 + 额外强化次数)
组合分数 = 所有有效副词条分数之和
```

例如单价为“暴击率 1.0、暴击伤害 1.2、攻击力% 0.8”，组合里有“暴击率 +1、暴击伤害、攻击力%、废词条”，则分数是 `1.0 × 2 + 1.2 + 0.8 = 4.0`。

未填写或单价为 0 的副词条不作为有效词条计分，在组合中归为“废词条”。“未出”表示还没有出现的副词条位置。当前规则会排除额外强化落在废词条上的组合，不只检查总分。

“本档要求”是该词数、该等级的分数门槛，等于门槛也通过。两个词数页签的门槛默认分别设置，不会自动同步；需要两边都一致时，点本侧页签顶部的“拷贝 N词 的本档要求”按钮，可把另一侧每档的门槛（右侧卡片权重）一键照搬过来，只搬“本档要求”这一列，不动卡片勾选。

每个等级档位右侧都有“递增下发”按钮：以该档门槛为 x，把更高档依次设为 x+1、x+2……（每高 3 档 +1），用来快速拉出一串递增门槛。从任意档点都生效——点 +6 就只往下填 +9/+12/+15，本档及更低档保持不动。

客户端已取消“最少有效种类”这一设置，不需要再配置它。

### 主属性优先于单价，但不会删除单价

| 部位 | 自动排除的同名副词条 |
| --- | --- |
| 1 号 | 生命值 |
| 2 号 | 攻击力 |
| 3 号 | 防御力 |
| 4–6 号 | 单选时排除同名副词条；多选时保留可能出现在另一种主属性盘上的词条；也可以选择“不限” |

被排除的词条不会参与当前任务的组合生成和计分，但它的单价仍保留在单价表和任务存档中。

例如选“攻击力%”作为主属性，只排除“攻击力%”，不会把固定值“攻击力”一并排除。更换主属性后，原有单价可以继续使用。

套装和 4–6 号主属性可以多选，部位仍为单选。所选主属性是“满足其中任意一个”，同一任务共用单价、档位门槛、卡片名单和处理额度。选择“不限”会清空具体主属性；取消最后一个主属性也会回到“不限”。

例如同时选攻击力%和暴击率，攻击力%仍可作为暴击率主属性盘的副词条，所以不能同时屏蔽两项单价。组合生成与计数会排除任何所选主属性都不可能对应的副词条组合。修改选择后需重新生成、检查卡片名单。若不同主属性需要不同规则，请保留为独立任务；已有任务不会自动合并。

## 6. 生成、勾选和计数

### 为什么不实时生成

修改单价、添加词条、更换主属性或切换任务后，预览可能显示“组合待生成”。点击“生成组合”才刷新组合；计算在后台执行，每档按 24 张分页显示。

预览过期不代表配置过期。保存和开始任务使用当前编辑值，不要求先刷新右侧卡片。

单独修改档位门槛会筛选已有预览；但如果单价等条件已经改变，仍应重新生成后再查看或挑卡。

### 必带词条

单价表每行右侧的“必带”用于筛选卡片。勾选多个时，卡片必须同时包含全部勾选词条，并满足该档分数门槛；初始 3 词、初始 4 词及各等级档位都使用这个条件。

已有预览会立即筛选，不重新穷举组合。已勾选数量随条件缩减，保存和开始任务只提交符合条件的已勾选组合，不自动勾选其他卡片。例如原先勾了 100 张，只有 35 张满足必带和门槛条件，则有效已选及保存名单为 35 张。

同一次编辑中取消“必带”，原先因这个条件隐藏的已勾选卡片可重新显示；手动取消的卡片不会自动勾上。保存后重新打开，只有已保存的有效名单，扩大范围需手动勾选或使用“全选当前可见”。

必带按任务保存，切换任务和复制任务会保留；“应用于所有任务”会同时复制当前单价与必带勾选，新建任务不继承。全任务卡片全选按每项任务自己的必带和门槛条件执行。

单价为 0 或被主属性排除的词条不会以该名称出现在卡片中；勾选这类词条为必带，会得到 0 张符合条件的卡片。仅勾选必带不把未生成的任务变成已生成；已生成后筛成 0 张则按有效空名单保存。

### 卡片名单的状态

| 方式 | 执行依据 |
| --- | --- |
| 未生成、未指定卡片名单 | 列表显示“未生成”，执行时跳过这项任务 |
| 已生成或已指定名单 | 按当前有效勾选名单执行，未列入的组合不通过 |
| 已生成后明确取消全部勾选 | 有效的空名单，已选数量为 0；匹配的盘子没有被接受的组合 |

首次点击“生成组合”完成后，会记录当时符合各档门槛和必带条件的默认勾选名单。仅修改单价、门槛或必带不会建立名单；尚未完成或失败的生成也不会让任务变成可执行。生成期间显示“计算中”，完成后显示数量。

任务列表右侧有“初始3词”和“初始4词”两列，每列显示“有效已选数量 / 符合条件数量”，条件包含门槛和必带，汇总 +0～+15 六档及全部分页。统计会在后台更新，不会为了未生成的任务穷举组合。

人工名单按任务保存，包含词数和等级档位。不要只检查 `+0`：盘子升到下一档时，也要能匹配该档允许的组合，否则可能被打弃置标记。

保存、切走或开始任务时，会按当前主属性、门槛和必带提交有效勾选。调整条件后，旧名单不一定仍覆盖你想要的全部组合，尤其是降低门槛或添加新词条时。需要扩大范围，就重新生成并检查相应页签，必要时使用“全选当前可见”。

### 底部数字是什么意思

底部计数与全选/取消按钮使用同一范围：当前“初始 3 词”或“初始 4 词”页签的全部等级档位。

| 数字 | 含义 |
| --- | --- |
| 组合共 | 当前页签组合库的总数，尚未按本档分数门槛筛选；组合库本身已排除废词条额外强化等不展示的组合 |
| 符合门槛 / 符合条件 | 达到各档要求并满足必带条件的组合总数，包括还没翻到的分页；勾选必带时显示“符合条件” |
| 已勾选 | 符合门槛及必带条件的组合中，当前被选中的数量 |

“全选当前可见”后，已勾选等于符合门槛数，不一定等于组合库总数。“取消当前可见”后，该页签的已勾选为 0，不会同时取消另一个词数页签。

翻页不会清除勾选。“试判”页签下的底部范围是两个词数页签合计，此时全选/取消也作用于两者。

## 7. 切走后，之前的卡片还有效吗

**有效。被清空的是右侧预览，不是任务的组合选择记录。**

例如：在任务 A 中挑好卡，切到任务 B 后，A 的单价、门槛和有效勾选已记录在任务链里。点击“开始任务”时，A、B 会按列表顺序分别使用自己的配置执行，不只执行屏幕当前显示的任务。

切回 A 后，可能需要点击“生成组合”才能重新看到卡片，已记录的勾选会用于恢复预览。无需为执行而逐项重新生成或重新挑选。

注意一个例外：“移除任务”是真的删除该任务。

## 8. 保存、另存为和应用到所有任务

### 哪些操作会写文件

| 操作 | 是否落盘 |
| --- | --- |
| 编辑、生成组合、挑卡、切换任务、试判 | 不自动写任务 YAML |
| 顶部“保存” | 将整条任务链及共用设置写入当前 YAML |
| 顶部“另存为” | 保存到另一份 YAML，并将它设为当前工作存档 |
| “开始任务” | 先自动保存整条任务链；保存失败则不开始执行 |

切换任务保留的是本次打开客户端期间的记录，不等于已经写入磁盘。退出前没有保存、也没有开始任务的修改，不应认为会自动恢复。

### 应用到所有任务

词条单价、当前任务限制和游戏内筛选的套装各有一次“应用于所有任务”，把当前这一项**复制**给任务链里此刻已经存在的每个任务，省掉逐个任务重复配置。

- 它只铺当时已有的任务：之后新建的任务拿自己的默认值，不会被这次应用绑住，也不会跟着改动。
- 只铺它自己那一项。铺单价不会动额度、套装或门槛，反之亦然。
- 铺完记得用顶部“保存”写进任务存档，否则只在本次客户端期间有效。
- 任务链为空时这三个按钮是灰的，先“新建任务”。

“选择套装”仍然打开套装列表勾选；勾完只是改了当前任务，要点“应用于所有任务”才会铺给其他任务。

## 9. 存档放在哪里，更新时怎么办

当前公共根目录是 `D:\WB_agent_out\zzz-ddtool\zzz-ddtool`，结构如下：

```text
zzz-ddtool/
  .zzz-ddtool-root
  user/
    plan/
      example.yaml
      example3.yaml
      其他任务存档.yaml
    last-config.json
    navigation-profile.json
  log/                    运行时产出：text/ 文本日志、captures/ 截图、stats/ 统计
  dist/
    某个版本/
      zzz-ddtool/
        zzz-ddtool.exe
        _internal/
        data/
          sets.json
          stats.json
```

任务 YAML 统一放在 `user/plan/`，不是 `presets`，也不放 AppData。上次打开的文件记录和导航配置放在同一公共 `user/` 中。

`.zzz-ddtool-root` 用于定位公共根目录。之后的新版本客户端放在该根目录下面的版本子目录中，共用这份用户数据，也共用公共 `log/`。不要把程序复制到根目录以外后，还假定它会自动找到原来的 `user/`。

同一时间只允许运行**一个**客户端实例（不同版本也算同一个）：重复启动会提示“程序已在运行”并退出。若确认没有实例在运行却提示已占用，删掉公共根下的 `.zzz-ddtool.lock` 再启动。

更新包只带程序和运行资源，不带**用户**任务 YAML。首次运行会把包里自带的示例（`data/examples/`，如 `example.yaml`）种进 `user/plan/`，**只种一次**：之后你改过或删掉的示例都不会被再次覆盖或补回。更新时保留公共 `user/` 和根目录标记，不需要逐版本复制存档；也不要只单独搬走 exe，它仍需要同目录的依赖和运行资源。

首次导入旧存档时，程序会将旧 `data/` 等目录中的 YAML 收纳到 `user/plan/`，保留原文件。同名而内容不同的存档会添加导入后缀，不覆盖已有存档。用户主动选择根目录之外的 YAML 时，仍可在原位置编辑。

## 10. 开始、暂停和停止

开始前确认游戏窗口化、比例和缩放符合当前标定；当前坐标按 1920×1080、16:9、系统缩放 100% 使用。还要确认目标套装、部位、主属性、材料和任务额度。

开始时会检查任务链是否为空，以及每项任务是否至少有一个可用的正权重副词条。只给被主属性屏蔽的词条设置单价，也属于没有可用单价。

每项任务有独立的处理额度。打开详情实际处理一件盘计作一个，强化多档不会当成多个盘；扫描阶段直接跳过的盘不占该额度。用满当前任务额度后，继续下一项任务。

- “暂停 / F9”：请求暂停，再按一次恢复。
- “停止 / F10”：请求停止，不会因为当前任务额度结束而重新继续。
- 运行中关闭窗口：先请求安全停止，再等执行线程结束后关闭。

暂停和停止在业务检查点及下一次输入动作前生效，导航、标定、筛选和强化途中也会响应。正在执行的 OCR、等待和一次完整点击/按键会先结束，避免留下未释放的键；停止后保留当前游戏页面供复核。出现“等待安全停止”时，不要反复点击开始，也不要假定进程已经结束。

处理流程是逐档判断、强化或打弃置标记，**不执行分解**。识别失败、页面不符或材料不足等异常可能停止任务链，应先查日志再处理。

主属性筛选展开后，目标未露出或位于面板底部点击无效区时，会向下滚动并重新识别，最多尝试 8 轮。已选择的词条不会重复点击；仍找不到时中断，并在日志中列出未选到的词条。

游戏筛选后没有盘是正常结果。确认仓库数量为零且网格都是空占位后，当前任务记为处理 0 件，继续下一项；仅仅识别不到等级不能作为空结果。

导航按“筛选结果是否整屏可见”分两条路径：

- **整屏可见**：筛选后总盘数不超过单屏容量（当前 9 列 × 4 行 = 36 个格位），实体盘从首行首列连续排列，其余格位都确认为游戏空占位。结果本来就在当前画面里，所以不切页置顶、不做末行延期、不发探底滚轮，直接整屏处理；强化某件盘后先在仓库原地简查并复用剩余候选，缓存缺失或简查失败才重新扫描核对。最后一件完成后无需恢复下一件。
- **长列表（不满足上面的条件）**：筛选后**也不置顶**——关闭筛选面板时游戏自己就把列表滚回了顶部，当前画面已经是顶部原点（切页置顶既不改变筛选结果也不改变视口，纯属多余，已删除）。直接按实测滚轮协议从顶部分屏向下遍历。强化后按保存的视口「切页置顶 → 批量滚回」，失败最多两次；两次仍不匹配就停止任务链。

判断“整屏”用的数量是游戏仓库显示的**筛选后总盘数**（包含满级、装备、锁定、弃置），不是“待处理数”“处理上限”或扣掉跳过项后的数量。恰好 36 个时必须靠总数区分“只有 36 个”和“长列表的前 36 个”，数量读不出来一律按长列表处理。

强化后允许由本件升级解释的等级降序前移，已经解决的前缀不要求保持原等级位置。总数变化、未处理后缀变化，或无法由本件升级解释的变化会使格位关联失效，这时停止任务链。只有页面或相位异常（例如窗口尺寸变化）才回退到既有置顶定位恢复。

## 11. 试判和排错

在“试判”页签填盘子等级、副词条和额外强化次数。输入的 `+0` 表示刚出现，`+1` 表示出现后又强化一次；未出现的位置留空。词条和强化次数应与盘子等级相符，否则可能无法推断初始词数。

点击“试判这件盘”只做当前任务的本地判断，不点击游戏，也不代替整条任务链的实际运行测试。

| 结果 | 含义 |
| --- | --- |
| `upgrade` | 允许继续强化到下一档 |
| `mark_discard` | 组合不通过，计划打弃置标记，不是分解 |
| `skip` | 命中跳过条件或保留满级盘等情况 |
| `stop` | 无法可靠判定，例如初始词数推断不明确 |

出问题时，先看窗口底部的运行状态和日志，记下失败原因、任务及步骤号，再查公共根 `log/text/ddtool.log` 和 `log/captures/` 对应截图。需要更多信息时，在顶部“日志设置”中开启详细级别。

不要仅凭“右侧没有卡片”判断任务丢失，也不要把“开始前检查通过”理解为后续识别一定成功。

## 12. 当前能力边界

- 已配置的规则与实际游戏识别是两回事。试判能验证规则，但不能验证真实盘面的 OCR、图标识别和点击位置。
- 锁定、弃置和装备跳过的当前支持状态，统一见 [运行限制与筛选](./运行限制与筛选.md) 第 3 节；不要将历史记录里的默认值或已停用判据当作当前保护。
- 稀有度读取及样本覆盖统一见 [识别标定](../技术/识别标定.md) 的“锁定与稀有度”部分；不能由配置开关推导实际识别一定成功。
- 首次运行、换分辨率、游戏更新或更换筛选方案后，应先用较小额度观察结果，不建议直接无监督处理整个仓库。
