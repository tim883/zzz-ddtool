# 02 运行限制、游戏筛选、已装备

## 1. 本次最多处理多少盘

配置：`task_chain` 中每个任务的 `max_discs`（新任务默认 100，至少 1）。窗口「当前任务限制」里设置「本次最多处理 N 个盘子」，切换任务会恢复各自的数量。

每个任务独立计数，前一个任务用满额度后继续下一个任务，不会占用后续任务的额度。扫描阶段已经跳过的格位不计数，打开详情处理的盘计 1。

计数口径（2026-10-05 明确）：**点开并读出盘面的盘计 1 件处理**；之后不管是升级、打标还是什么都不做，都算。
「原本就有弃置标记、重新判断后维持不动」的盘也计 1 件，并进结果清单、计入「判定弃置」，但**不计入
「实际打上弃置标记」**（没按 R 就不算那本账）。三本账各自独立：处理计数 / 判定弃置 / 实际打标。

旧配置中未填写任务级 `max_discs` 时，每个任务沿用 `run.max_discs` 作为默认额度；没有任务链的命令行运行仍使用 `run.max_discs`。

到上限后**停在原地，不翻页**——翻页尾巴上那下 Esc 按在网格会把仓库退到功能页。

### 组合预览

修改权重、添加词条或切换任务后，点击「生成组合」刷新右侧预览。计算在后台进行，修改配置会取消旧计算；保存和开始任务均使用当前编辑值，无需等待预览。

每档按 24 张分页，只为符合门槛的组合创建卡片。翻页保留勾选；「全选当前可见」和「取消当前可见」作用于当前词数页签下所有符合门槛的组合，包括尚未翻到的页。底部计数也只统计该页签：组合共计是完整组合数，符合门槛是筛选后总数，已勾选是筛选后选中数。全选后已勾选等于符合门槛，取消后为 0。

客户端不再使用「最少有效种类」，载入旧配置时会将该限制关闭。筛选使用词条单价、档位门槛和组合勾选；命令行配置仍兼容旧字段。

主属性屏蔽优先于词条单价：1 号自动排除生命值、2 号排除攻击力、3 号排除防御力；4–6 号主属性支持多选，也可选「不限」。单选时排除同名副词条；多选时保留能出现在另一种主属性盘上的副词条，并排除所有所选主属性都不可能对应的组合。排除只作用于组合生成和运行判定，单价表与任务存档始终保留原单价。固定值与百分比是不同词条，排除生命值不会同时排除生命值%。载入存档会保留全部合法主属性选择。

保存不依赖生成组合。任务未生成时显示“未生成”并跳过执行；生成后的选中组合保存为白名单，空白名单也是有效配置，不回退到权重接受。切换任务会提交当前编辑内容，任务链中之前的任务依然参与运行，各自的权重、门槛、额度和组合勾选独立。修改后须保存任务存档才会落盘。

### 应用到所有任务

词条单价、当前任务限制和游戏内筛选的套装各有一个「应用于所有任务」按钮，把当前这一项**复制**给任务链里此刻已经存在的每个任务。

- 只铺当时已有的任务：之后新建的任务拿自己的默认值，不会被这次应用绑住，也不跟着改。
- 一次只铺它自己那一项：铺单价不动额度、套装和门槛，反之亦然。
- 只改内存里的任务链，仍需顶部「保存」才写进任务 YAML。
- 任务链为空时按钮置灰。套装依然点「选择套装」开弹窗勾选，勾完只改当前任务。

全部用户配置放在公共根目录的 `user/` 下，不放 AppData，也不随新版程序打包：

- `user/plan/`：所有任务 YAML，包括 `example.yaml`、`example3.yaml`。它们和其他存档平等，可正常修改保存。
- `user/last-config.json`、`user/navigation-profile.json`：上次打开的存档和本机导航配置。

根目录由 `.zzz-ddtool-root` 标记；在根目录下任意版本子目录中启动 exe，都会使用这份公共 `user/`。新版只更新程序及运行资源；`data/` **直属**不再包含任务 YAML，随包示例改放 `data/examples/`。第一次运行会把 `data/examples/` 里的示例种进 `user/plan/`，**只种一次** —— 之后用户改过或删掉的都不会被覆盖或补回；同时会把旧 `data/` 等目录中的 YAML 导入 `user/plan/`，不覆盖已有文件，原文件保留，同名而内容不同的存档加导入后缀，保证两份都保留。示例的新版本走界面「获取公共示例」按需下载，**同样不覆盖本地文件**：内容不同时并列保存。默认打开/另存目录也是 `user/plan/`；用户主动选择根目录以外的文件时仍可在原位置编辑。

## 2. 进驱动盘后的筛选顺序

能按键就按键，不扫关闭按钮。

1. 点左下筛选漏斗
2. 点「重置」（先清空游戏里上次留下的条件）
3. 在中间「游戏内筛选」里选套装、点部位、必要时选主词条。套装要开弹窗勾选，部位和主词条
   直接摆在面板上。部位 1–6 单选，右侧卡片和左侧权重是这一号的策略，换号会换一套。
   1–3 主词条固定不选；4/5/6 只出游戏里这个号能出的主词条，支持多选。同一任务的多种主词条共用单价、门槛和卡片名单；规则不同则分成独立任务。
4. 根据当前任务右侧初始 3 词、4 词的 **0 级组合**自动设置副属性筛选：选择一组词条，命中数量从最低需要的数量一直勾到 4。
5. **Esc 关掉筛选面板**，回到驱动盘列表，再开始逐张处理

关筛选用 Esc，比 OCR 找叉再点快，也不依赖关闭按钮模板。

漏斗点击：1920×1080 约 **(166, 906)**（白圈）。**(224, 930) 是拆解蓝标，不能点**——
点上去就进拆解流程了。`gamefilter.py::_refuse_dismantle` 会在点击前做一次坐标兜底检查。

预设写法：

```yaml
game_filter:
  sets: ["折枝剑歌"]
  slot: 4
  mainstats: ["暴击伤害"]
```

`sets: []` 和 `mainstats: []` 表示不再添加对应条件。号位始终单选：省略 `slot` 时默认 4 号；兼容旧字段 `slots` 时仅取第一个合法号位，空列表也默认 4 号，不表示所有号位。新配置使用 `slot`；需要处理多个号位时，在 `task_chain` 中为每个号位分别建立任务，各自保存规则和卡片名单。

### 自动副属性筛选

无需手动填写副属性条件。可执行任务以实际选择的初始 3 词 / 4 词 **0 级组合**推导副属性筛选；未生成任务跳过。两个初始词数页签共同决定一组筛选，游戏筛出的所有等级盘仍沿用各自档位的判断和强化逻辑。

游戏统计的是所选词条中出现了几种，数量对整组词条共同生效，不是盘子的总词条数。例如选双暴、数量 2/3/4，就能保留所有双暴盘；只选数量 1 会使补出另一个暴击词条的盘离开列表，因此工具始终补齐最低命中数到 4。

工具比较不同词条集合，选择覆盖全部目标且理论候选组合数最少的单轮方案。同样的候选范围优先少选词条。该估计不代表仓库里实际盘子数量；筛出的额外组合仍由工具精确判定。所有词条均为真正的游戏副属性，已屏蔽的主属性和「废词条」「未出」占位符不会被点选。

筛选以「0 级要求比高等级宽松」为任务前提，只根据 0 级组合推导，高等级不会另开一轮。若接受全废组合、没有 0 级目标或无法缩小范围，工具不加副属性条件。开始任务时，状态及日志会显示实际使用的词条、命中数量或不加条件的原因。

### 全局标签策略接口

界面配置栏「硬过滤（任务链共用）」组最上面两个勾就是这两个开关：「判断后打上弃置标记」「判断后打上锁定标记」，默认都勾上（＝保持原有行为）。同一组设置也可以直接在任务 YAML 顶层写：

```yaml
labels:
  discard: false
  save: false
```

`discard: false`（取消勾选「判断后打上弃置标记」）**只停发 R**：判为弃置的盘在游戏里不留弃置标记，但判断结果、处理计数、结果清单和统计口径照旧——仍然算被判为弃置。盘处于锁定状态时，仍照旧先按 T 解锁并确认，避免直接 R 的确认弹窗，只是不再按 R；盘没锁就不读标签、不按键。标签读数拿不准时不为一个不发的键停链。摘标记（进强化页前那一步）属于强化流程，不受这个开关影响，照常执行。

`save: true` 时，本轮实际强化过且最终判定升满保留的盘子，退出强化页后核对等级、品质、词条和原状态：未锁定则按一次 T，已锁定不再按。R/T 按后都只快速检查右下角标签提示，不重读整盘；读不清只重读，仍无法确认就停止，不重复按键。完成后才记录标签成功、恢复仓库导航。

`save: false`（取消勾选「判断后打上锁定标记」）关闭保留锁定收尾：不读盘面核对、不按 T，也不记标签输入；仍记录升满保留成功，判断、计数和结果清单不变。原本满级而直接跳过的盘不执行保留收尾。旧配置默认两标签均为 `true`，界面载入和保存保持这些值。两个开关的界面回显、写回和不发键的离线覆盖已有用例，本轮未操作游戏验证。

## 3. 格子上的状态标记（锁定 / 弃置 / 装备）

扫描（看列表）时会读每格右下角的标记：**浅灰圆盘挂锁 = 已锁定**、**红圆牌 = 已弃置**（互斥，不会同时出现）。
识别一律做，**要不要因此跳过由任务 YAML 决定**：

- `skip_locked: true`（默认开）/ `skip_discarded: true` → 命中就跳过这一格：不点开、不读词条、不占处理计数；
- 对应开关关掉 → 该盘照常点开处理；
- 标记拿不准（判据中间带）且该状态配了跳过 → 重拍再看，仍拿不准就**停止整轮**，不会猜。

**非 S 级固定跳过，没有开关**（2026-10-12 删除「跳过非S级」选项）：稀有度由面板「等级03/15」的分母得出
（15 = S、12 = A、9 = B），确认是 A/B 就跳过——不强化、不打标、不进强化页。**但它仍会被点开**：格子上虽然画着
盘面自带的稀有度小牌（金色 `S`，见 [仓库说明](../参考图/驱动盘仓库/说明.md)），当前代码不读它，扫描只读「等级」数字
与锁定 / 弃置标；格子上的「等级」标签不带上限，所以稀有度只有点开后才读得到，非 S 盘照计 1 件处理、照占「本次最多处理 N」的额度。
上限读不出（未知）时按不跳过处理，宁可不跳，也不误丢好盘；A/B 上限的 12 / 9 仍缺真机样本，见 [识别标定](../技术/识别标定.md)。

**装备（格子右上角圆形角色头像）当前不判断**：判据缺独立答案卷、识别不准，已暂时停用
（扫描不再看头像；`skip_equipped` 字段、界面控件与存档值保留，界面标注「跳过已装备（无法跳过）」、勾选不生效）。装备盘与普通盘一样处理。
恢复方法见 [识别标定](../技术/识别标定.md) 的「已装备头像」段。图片与游戏含义见
[仓库参考说明](../参考图/驱动盘仓库/说明.md) 和 [筛选参考说明](../参考图/驱动盘筛选/说明.md)。

## 4. 套装展示

当前界面用按名字生成的色块和**完整套装名**，字号自适应；选择时以全名文字区分，不是只显示前两字。套装真图外置不属于当前待办，不能因缺少真图要求重新开发已完成的套装展示。
