# 驱动盘任务管理器使用说明

适用日期：2026-10-02。本文按当前客户端实现说明，不把计划中的功能当成已有功能。

## 1. 这个窗口叫什么

我建议叫 **驱动盘任务管理器**，简称 **任务管理器**。

它管理的是一整条处理任务链：配置筛选条件、设置词条单价和档位要求、选择组合、保存任务存档，再启动执行。右侧卡片只是当前任务的组合预览，不是全部功能，所以不适合叫“卡片生成器”。

“客户端”可以继续用于区分它和游戏；日常操作时，用“任务管理器”更明确。当前程序窗口标题仍是“驱动盘强化辅助”，本文的名称是命名建议，不代表已经修改了窗口标题。

## 2. 先分清这几个东西

| 名称 | 含义 |
| --- | --- |
| 任务 | 任务链中的一项，有自己的部位、套装、主属性、单价、门槛、组合勾选和处理数量 |
| 任务链 | 左侧列表中的全部任务，按从上到下的顺序执行 |
| 任务存档 | `user/plan/` 下的一份 YAML，保存整条任务链及共用设置 |
| 组合卡片 | 当前任务可能出现的副词条组合，用于查看分数和选择允许的组合，不是仓库里已经识别到的真实盘子 |

`example.yaml`、`example3.yaml` 和其他 YAML 都是普通任务存档。名字里有 `example`，不代表只读、临时或可以在更新时覆盖。

## 3. 最常用的一次操作

1. 点击“打开”选择已有任务存档；或者点击“新建任务”从空任务开始。
2. 给任务起一个能认出来的名字，例如“4号双暴”。
3. 在“游戏内筛选”中选择部位、套装和主属性。
4. 添加需要的副词条，填写单价。
5. 分别设置“初始 3 词”和“初始 4 词”各档的“本档要求”。
6. 设置当前任务最多处理多少个盘子。
7. 需要查看或挑选组合时，点击“生成组合”；不需要人工挑卡时，可以不生成。
8. 新建或复制下一项任务，配置完成后调整任务链顺序。
9. 点击“保存”。首次使用或想保留另一套方案时，使用“另存为”。
10. 确认游戏环境和材料，点击“开始任务”。建议先给每项任务设置较小额度，观察实际结果。

打开另一份存档前，先保存当前修改。切换任务会保留编辑内容，但打开另一份存档是在切换整条任务链，不应当把两种操作混为一谈。

## 4. 窗口各区域

### 左侧：任务链

- “新建任务”：创建空任务，不继承前一项的单价和组合勾选。
- “复制任务”：复制当前任务的配置和勾选，再给它独立的新任务身份。
- “上移 / 下移”：改变执行顺序。
- “移除”：删除这项任务，不只是隐藏它。
- 点击列表中的任务：先记录当前编辑内容，再加载选中的任务。

同一部位可以有多个任务，例如不同套装或主属性分别设任务。它们的设置是独立的，不是一个部位只能存一套。

### 中间：当前任务的配置

词条单价、游戏内筛选和处理额度都属于当前任务。硬过滤则由整条任务链共用。

| 设置 | 作用范围 |
| --- | --- |
| 部位、套装、主属性 | 当前任务 |
| 词条单价、各档位要求 | 当前任务 |
| 手工选择的组合 | 当前任务 |
| 本次最多处理多少个盘子 | 当前任务，独立计数 |
| 只要 S 级、跳过锁定、跳过已装备、跳过已有弃置标记 | 整条任务链共用 |

修改当前任务的部位，是修改这项任务，不是自动切换到另一个已有任务。

中间这一栏从上到下是：词条单价、硬过滤、当前任务限制、游戏内筛选。“游戏内筛选”分成两块：上面是套装（点“选择套装”开弹窗勾选），下面是部位 1–6 与主词条。部位和主词条都直接摆在面板上，不再进弹窗；1–3 号位主词条固定，只显示提示，4/5/6 号位才出本部位能出的主词条单选项。词条单价、当前任务限制和套装各带一个“应用于所有任务”，用来把这一项一次铺给任务链里已有的任务（详见第 8 节）。

### 右侧：组合预览与试判

- “初始 3 词”：盘子初始拥有 3 条副词条的升级路径。
- “初始 4 词”：盘子初始拥有 4 条副词条的升级路径。
- `+0 / +3 / +6 / +9 / +12 / +15`：在对应等级检查组合。
- “试判”：手工输入一件盘，检查当前任务会如何判定，不操作游戏。

“初始 3 词”盘升到出现第 4 条后，仍属于初始 3 词的路径，不会因此变成“初始 4 词”任务。

## 5. 单价、门槛和主属性

### 单价怎样计算

单价是你给副词条的相对价值，不是游戏中的货币价格，也不是词条实际数值。

每条有效副词条的分数为：

```text
词条分数 = 单价 × (1 + 额外强化次数)
组合分数 = 所有有效副词条分数之和
```

例如单价为“暴击率 1.0、暴击伤害 1.2、攻击力% 0.8”，组合里有“暴击率 +1、暴击伤害、攻击力%、废词条”，则分数是 `1.0 × 2 + 1.2 + 0.8 = 4.0`。

未填写或单价为 0 的副词条不作为有效词条计分，在组合中归为“废词条”。“未出”表示还没有出现的副词条位置。当前规则会排除额外强化落在废词条上的组合，不只检查总分。

“本档要求”是该词数、该等级的分数门槛，等于门槛也通过。两个词数页签的门槛分别设置，不会自动同步。

客户端已取消“最少有效种类”这一设置，不需要再配置它。

### 主属性优先于单价，但不会删除单价

| 部位 | 自动排除的同名副词条 |
| --- | --- |
| 1 号 | 生命值 |
| 2 号 | 攻击力 |
| 3 号 | 防御力 |
| 4–6 号 | 当前单选的主属性；也可以选择“不限” |

被排除的词条不会参与当前任务的组合生成和计分，但它的单价仍保留在单价表和任务存档中。

例如选“攻击力%”作为主属性，只排除“攻击力%”，不会把固定值“攻击力”一并排除。更换主属性后，原有单价可以继续使用。

套装可以多选；部位以及 4–6 号的主属性都是单选。套装不选、主属性选择“不限”，表示不加对应筛选条件。

## 6. 生成、勾选和计数

### 为什么不实时生成

修改单价、添加词条、更换主属性或切换任务后，预览可能显示“组合待生成”。点击“生成组合”才刷新组合；计算在后台执行，每档按 24 张分页显示。

预览过期不代表配置过期。保存和开始任务使用当前编辑值，不要求先刷新右侧卡片。

单独修改档位门槛会筛选已有预览；但如果单价等条件已经改变，仍应重新生成后再查看或挑卡。

### 两种选择方式

| 方式 | 执行依据 |
| --- | --- |
| 没有人工改变过勾选 | 按当前单价、档位门槛和默认组合规则判定 |
| 人工勾选、取消，或点击全选/取消按钮 | 保存允许的组合名单，未列入的组合不通过 |

仅点击“生成组合”不会自动切换成人工名单模式。预览中默认勾选的卡片，可以只是默认规则的展示。

人工名单按任务保存，包含词数和等级档位。不要只检查 `+0`：盘子升到下一档时，也要能匹配该档允许的组合，否则可能被打弃置标记。

保存、切走或开始任务时，会按当前主属性和门槛提交有效勾选。调整条件后，旧名单不一定仍覆盖你想要的全部组合，尤其是降低门槛或添加新词条时。需要扩大范围，就重新生成并检查相应页签，必要时使用“全选当前可见”。

### 底部数字是什么意思

底部计数与全选/取消按钮使用同一范围：当前“初始 3 词”或“初始 4 词”页签的全部等级档位。

| 数字 | 含义 |
| --- | --- |
| 组合共 | 当前页签组合库的总数，尚未按本档分数门槛筛选；组合库本身已排除废词条额外强化等不展示的组合 |
| 符合门槛 | 达到各档要求的组合总数，包括还没翻到的分页 |
| 已勾选 | 符合门槛的组合中，当前被选中的数量 |

“全选当前可见”后，已勾选等于符合门槛数，不一定等于组合库总数。“取消当前可见”后，该页签的已勾选为 0，不会同时取消另一个词数页签。

翻页不会清除勾选。“试判”页签下的底部范围是两个词数页签合计，此时全选/取消也作用于两者。

## 7. 切走后，之前的卡片还有效吗

**有效。被清空的是右侧预览，不是任务的组合选择记录。**

例如：在任务 A 中挑好卡，切到任务 B 后，A 的单价、门槛和有效勾选已记录在任务链里。点击“开始任务”时，A、B 会按列表顺序分别使用自己的配置执行，不只执行屏幕当前显示的任务。

切回 A 后，可能需要点击“生成组合”才能重新看到卡片，已记录的勾选会用于恢复预览。无需为执行而逐项重新生成或重新挑选。

注意一个例外：“移除任务”是真的删除该任务。

## 8. 保存、另存为和应用到所有任务

### 哪些操作会写文件

| 操作 | 是否落盘 |
| --- | --- |
| 编辑、生成组合、挑卡、切换任务、试判 | 不自动写任务 YAML |
| 顶部“保存” | 将整条任务链及共用设置写入当前 YAML |
| 顶部“另存为” | 保存到另一份 YAML，并将它设为当前工作存档 |
| “开始任务” | 先自动保存整条任务链；保存失败则不开始执行 |

切换任务保留的是本次打开客户端期间的记录，不等于已经写入磁盘。退出前没有保存、也没有开始任务的修改，不应认为会自动恢复。

### 应用到所有任务

词条单价、当前任务限制和游戏内筛选的套装各有一次“应用于所有任务”，把当前这一项**复制**给任务链里此刻已经存在的每个任务，省掉逐个任务重复配置。

- 它只铺当时已有的任务：之后新建的任务拿自己的默认值，不会被这次应用绑住，也不会跟着改动。
- 只铺它自己那一项。铺单价不会动额度、套装或门槛，反之亦然。
- 铺完记得用顶部“保存”写进任务存档，否则只在本次客户端期间有效。
- 任务链为空时这三个按钮是灰的，先“新建任务”。

“选择套装”仍然打开套装列表勾选；勾完只是改了当前任务，要点“应用于所有任务”才会铺给其他任务。

## 9. 存档放在哪里，更新时怎么办

当前公共根目录是 `D:\WB_agent_out\zzz-ddtool\zzz-ddtool`，结构如下：

```text
zzz-ddtool/
  .zzz-ddtool-root
  user/
    plan/
      example.yaml
      example3.yaml
      其他任务存档.yaml
    last-config.json
    navigation-profile.json
  dist/
    某个版本/
      zzz-ddtool/
        zzz-ddtool.exe
        _internal/
        data/
          sets.json
          stats.json
```

任务 YAML 统一放在 `user/plan/`，不是 `presets`，也不放 AppData。上次打开的文件记录和导航配置放在同一公共 `user/` 中。

`.zzz-ddtool-root` 用于定位公共根目录。之后的新版本客户端放在该根目录下面的版本子目录中，共用这份用户数据。不要把程序复制到根目录以外后，还假定它会自动找到原来的 `user/`。

更新包只带程序和运行资源，不带任务 YAML。更新时保留公共 `user/` 和根目录标记，不需要逐版本复制存档；也不要只单独搬走 exe，它仍需要同目录的依赖和运行资源。

首次导入旧存档时，程序会将旧 `data/` 等目录中的 YAML 收纳到 `user/plan/`，保留原文件。同名而内容不同的存档会添加导入后缀，不覆盖已有存档。用户主动选择根目录之外的 YAML 时，仍可在原位置编辑。

## 10. 开始、暂停和停止

开始前确认游戏窗口化、比例和缩放符合当前标定；当前坐标按 1920×1080、16:9、系统缩放 100% 使用。还要确认目标套装、部位、主属性、材料和任务额度。

开始时会检查任务链是否为空，以及每项任务是否至少有一个可用的正权重副词条。只给被主属性屏蔽的词条设置单价，也属于没有可用单价。

每项任务有独立的处理额度。打开详情实际处理一件盘计作一个，强化多档不会当成多个盘；扫描阶段直接跳过的盘不占该额度。用满当前任务额度后，继续下一项任务。

- “暂停 / F9”：请求暂停，再按一次恢复。
- “停止 / F10”：请求停止，不会因为当前任务额度结束而重新继续。
- 运行中关闭窗口：先请求安全停止，再等执行线程结束后关闭。

暂停和停止在安全检查点生效，通常等当前盘处理结束，不是按键瞬间强行中断游戏操作。出现“等待安全停止”时，不要反复点击开始，也不要假定进程已经结束。

处理流程是逐档判断、强化或打弃置标记，**不执行分解**。识别失败、页面不符或材料不足等异常可能停止任务链，应先查日志再处理。

## 11. 试判和排错

在“试判”页签填盘子等级、副词条和额外强化次数。输入的 `+0` 表示刚出现，`+1` 表示出现后又强化一次；未出现的位置留空。词条和强化次数应与盘子等级相符，否则可能无法推断初始词数。

点击“试判这件盘”只做当前任务的本地判断，不点击游戏，也不代替整条任务链的实际运行测试。

| 结果 | 含义 |
| --- | --- |
| `upgrade` | 允许继续强化到下一档 |
| `mark_discard` | 组合不通过，计划打弃置标记，不是分解 |
| `skip` | 命中跳过条件或保留满级盘等情况 |
| `stop` | 无法可靠判定，例如初始词数推断不明确 |

出问题时，先看窗口底部的运行状态和日志，记下失败原因、任务及步骤号，再查程序目录下的 `log/text/ddtool.log` 和 `log/captures/` 对应截图。需要更多信息时，在顶部“日志设置”中开启详细级别。

不要仅凭“右侧没有卡片”判断任务丢失，也不要把“开始前检查通过”理解为后续识别一定成功。

## 12. 当前能力边界

- 已配置的规则与实际游戏识别是两回事。试判能验证规则，但不能验证真实盘面的 OCR、图标识别和点击位置。
- 锁定状态读取依赖 OCR 对“解除锁定”等文字的识别，实际图标按钮存在识别限制；稀有度也尚未可靠读取，盘子数据默认按 S 级处理。因此，不能仅凭勾选“跳过锁定”或“只要 S 级”就认为受到了绝对保护。
- 满级、已装备头像和已有弃置标记有扫描阶段的跳过逻辑，但仍受图像识别准确性影响。
- 首次运行、换分辨率、游戏更新或更换筛选方案后，应先用较小额度观察结果，不建议直接无监督处理整个仓库。
